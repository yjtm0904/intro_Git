# 「AIっぽさ」の市場調査と、事務の型紙に合う直し方

- 作成：文体リサーチャー（2026-11-13）／依頼：事業責任者（D-015「AIっぽさをなくす改善の工程」の1段目）
- 対象：note・ブログ・編集者・研究で「AIっぽい文章」と呼ばれるもの、その影響の根拠、直し方、我々の記事（102・106・203の無料部分を精読、ほか8本は機械チェック）
- 成果物：本レポート／`05_operations/tools/style-lint/patterns.json`（58パターン）
- 前提：人間が書いたように偽る方法（架空の体験・実績、わざとの誤字、AI検出の回避）は扱わない。AI活用の開示は維持する。目的は読者にとっての読みやすさ・具体性・信頼。

## 0. エグゼクティブサマリー

1. **言説は多いが、ほとんどが経験則。** noteの5つのキーワード（AI文章・AIライティング・文章術・ライティング・AI執筆）の人気記事220本のうち27本（12%）がAIっぽさを扱い、タグ「AIっぽさ」は713本ある。27本中23本は無料記事で、全文を読んだ10本中5本は自分の有料記事・メルマガ・診断への導線で終わる。挙がる特徴の上位5つは、①決まり文句（書き出し・締め・「〜することが重要です」）②整いすぎ・単調 ③具体性と一次情報の欠如 ④硬い語・抽象語・過剰な敬語 ⑤構成と記号の型（何でも3つにまとめる、太字、ダッシュ）。
2. **日本語で実測の裏付けがあるのは「読点が多い」くらい。** ネット上の「AIらしさ」の指摘148件を実測と照合した学士論文では、裏付けられたのは1件だけだった（査読なし）。機械による判別の研究は機能語や読点の位置で高い精度を出すが、人が挙げる特徴とは重ならない。人は見分けが苦手で、手がかりの使い方も誤る（Jakesch ほか 2023）。
3. **「AIっぽい文章は売れない」を直接示すデータは見つからなかった。** 強い根拠があるのは「AIが作ったと表示・認識されると、信頼や評価が下がる」こと（事前登録13実験・5,000人超の Schilke & Reimann 2025、4,976人の Altay & Gilardi 2024）。後者は原因を「人の監督なしにAIが全部書いた」という受け取り方に求めている。検索順位とAI利用の相関はほぼ0（Ahrefs、60万ページ）、Googleも作り方より品質を見ると明言している。
4. **我々の記事のAIっぽさは「SEOブログ調」ではなく「検証報告書調」。** 定番の決まり文句・抽象語・敬語・記号を拾う40種のパターンは、11本の無料部分で0件だった。代わりに次の5つが目立つ。①無料記事8本すべてが「## 結論：」「## まとめ：」の同じ骨組み（16件）②制作工程の内部用語「執筆とは別の新しい実行」（101・102・203）③同じ注意書きの繰り返し（「AIの出力は毎回少しずつ変わります」「（未検証）」で計19件）④丸かっこの挿入の多さ（曜日を除いて1,000字あたり8.2〜9.1個。言説側のnote記事10本は曜日込みでも0〜3.5個、中央値1.2個）⑤「この記事では〜しません」「測っていないため〜」という否定の宣言。
5. **我々に合う直し方は「人間らしく崩す」ではなく「型と繰り返しを削り、検証の事実を前に出す」。** 文体ルール15個、編集の5工程（書く前の文体ガイド→機械チェック→AIに指摘だけさせる→人が直す→冒頭の音読）、採点基準1〜5を提案する（§6）。現状の採点は102・203が2、106が3。公開の条件を4以上にすることを勧める。
6. **開示文はやめずに、具体的にする。** 「AIが何を作り、人が何をどう確かめたか」を書く。開示による不利の主因が「人の監督なし」という受け取り方なら、ここを具体的にするのが最も筋がよい（我々の文面での効果は未検証の仮説）。
7. **決めてほしいこと（§6.6）**：ガイドライン3か所の変更（注意書きは1記事1回、見出しのラベルをやめる、検証情報の書き方）と、102（11/16公開予定）でのパイロット。

### 2.5 批判的に見るべき点

- **実測の裏付けが乏しい。** 大西（2025）は、ネット上の指摘148件のうち実測と一致したのは「読点が多い」の1件だけと報告（学士論文・査読なし、二次情報で確認）。
- **機械と人は見ているものが違う。** 在津・金（2023）は機能語の比率などで98.1%の精度で判別した。言語処理学会（2026）の発表では、LLMは日本語母語話者がよくする誤用をほとんど出さない、表記の選び方が収束する、モデルごとに言い回しの癖がある、と報告されている。どれも読者が意識して気づく特徴ではない。
- **人の見分けは当てにならない。** Jakesch ほか（2023、6実験・4,600人）。人は一人称・縮約形・家族の話題を「人間らしさ」の手がかりにして誤る。
- **英語の特徴の流用。** ダッシュ・三つ組・「XだけでなくY」は英語圏の集計で、モデルによって差がある（Gemini 3 Pro は人より少ないとの報告）。日本語の記事に同じ重みで当てはまる保証はない。
- **ポジショントーク。** 読んだ10本中5本（N1・N2・N6・N8・N10）は自分の商品・メルマガ・個別診断への導線で終わる。「AIっぽいと売れない」は商品の前振りになっている面がある。反論側のN10（「売れないのはAIのせいではなく、何を誰に売るかだ」）も診断サービスの導線。N5は「声に出して読む工程」を書いたが実際はしていなかったと訂正している。誠実な訂正だが、このジャンルの手法が検証されずに語られている例でもある。
- **note公式の方針。** AIで書いた記事の扱いについてのnote公式の規定は見つからなかった。見つかったのはAI学習の対価還元と、学習への意向表明（オプトアウト）の仕組み。

### 3.2 評価

- 「AIっぽい文体が購入率を下げる」を直接測った調査は、日本・海外とも見つからなかった。この主張の根拠は事例と経験則。

### 6.5 patterns.json の使い方と限界

- 58パターン（warn 23・info 35）、15分類。各要素は id・category・regex（Pythonの正規表現）・why・suggest・severity。
- 全58パターンに正例と負例のテストを当て、すべて期待どおりに動くことを確かめた。11本の無料部分では18種、言説側のnote記事10本では39種が一致した（後者は例として引用された表現も拾う）。
- 調整済みの誤検出：飾りの区切り線（「――――」）をダッシュとして拾わない。必須の【検証情報】・最終更新日・［図解］の行をラベル行として拾わない。長文の判定でリンクのURLを数えない。「まとめて送る」を「まとめ」見出しとして拾わない。
- 1行ごとに照合する前提。段落をまたぐ型（「まず…次に…最後に」が段落をまたぐ場合など）は拾えない。
- info は誤検出がありうる前提の項目（「ではなく」は自然な日本語でも使う）。数を減らすことを目的にしない。
- 実行スクリプトは今回作っていない（指定外のファイルのため）。次の工程で compliance-lint と同じ除外処理で読み込む形にするのがよい。それまでの手動の実行例（無料部分だけを見る）：

```bash
cd /home/user/intro_Git/note-business
python3 -I -B - 03_content/articles/102-year-end-adjustment-reminders.md <<'EOF'
import json, re, sys
pats = json.load(open("05_operations/tools/style-lint/patterns.json", encoding="utf-8"))
lines = open(sys.argv[1], encoding="utf-8").read().split("\n")
skip = lines[0] == "---"  # YAMLのメタ情報
code = False
for no, line in enumerate(lines, 1):
    if skip:
        skip = not (no > 1 and line.strip() == "---")
        continue
    if "ここから有料" in line or line.strip() == "---":
        break  # 無料部分だけ（末尾の定型文も除く）
    if line.strip().startswith("```"):
        code = not code
        continue
    if code or line.strip().startswith("<!--"):
        continue
    for p in pats:
        if re.search(p["regex"], line):
            print(f'L{no} {p["severity"]:4} {p["id"]}: {line.strip()[:50]}')
EOF
```

### 6.7 採らない方法

| 方法 | 理由 |
|---|---|
| わざと誤字・言い間違いを残す（C16） | 作者を偽る手法。LLMは誤用をほとんど出さないという研究（ANLP 2026）を逆手に取ることになる。N5自身も読みにくくなったと報告 |

| AI検出の回避ツール（C17） | 目的が作者を偽ることにある |
| 開示をやめる・目立たなくする | オーナー決定・法務の方針。研究上も、開示の不利への対策は隠すことではなく具体的に書くこと |
