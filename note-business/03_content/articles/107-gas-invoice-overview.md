## 請求書の自動化は、4枚のシートと「確かめてから送る」設計で考える

締めのたびに、取引先ごとの請求書をひな形へ手で写している。GASで自動化できると聞いたが、何が危ないのか分からない。

シートは、取引先マスタ・請求明細・請求書のひな形・送付記録の4枚で考えます。GAS（Google Apps Script）には明細を集めてひな形に写す作業をさせ、送る前の確認は人が行います。下に、列の構成と、1社分の請求書シートを作る49行の最小コードを載せました。PDF化とメールの送付は扱いません。

【検証情報】検証日：2026-11-08／使ったツール：Googleスプレッドシート、Google Apps Script、Node.js 22
検証方法：架空の取引先2社・明細4行で、Googleのサービスを再現したNode.jsのテストを9件行い、すべて成功しました。最初の版は、税率を「5%」とした明細を「10%」と表示したまま合計から外し、エラーも出しませんでした。今は品目名を示して止まります。Googleの実際の環境での確認は【オーナー確認待ち：実機確認の日付とアカウントの種類（個人／Google Workspace）】

## 自動化に向く請求業務・向かない請求業務

向く
- 締め日が決まっていて、毎月同じ形の請求書を作る
- 取引先が10社以上ある
- 明細をスプレッドシートで管理できる

向かない
- 会計ソフトや請求書発行サービスで発行している
- 取引先ごとに書式や提出の方法が違う
- 1社の明細が月に16行以上ある。明細欄は15行まで
- Googleアカウントやスクリプト（GAS）を業務で使えない

## 全体像：取引先マスタ→請求明細→請求書→送付記録

### 各シートの列の構成

列は有料の「GAS請求書パック」と同じです。ここで作った3枚は、そのまま使えます。

- 取引先マスタ：A 取引先コード／B 取引先名／C 部署／D メール。コードは重複不可
- 請求明細：A 対象月／B 取引日／C 取引先コード／D 取引先名／E 商品コード／F 品目／G 数量／H 単価（税抜）／I 税率／J 金額。税率は10%か8%。D・Jは表示用、Eは任意
- 請求書レイアウト：値を入れたい場所に {{取引先名}} のように書く。13行目から15行が明細欄。自社名や振込先は直接書く
- 送付記録：送付まで自動にするときの、二重送信を防ぐ台帳。GAS請求書パックの「準備」メニューで作る

## 事故を防ぐ3つの原則

1. 下書きで確認：メールは下書きまでにし、人が確かめてから送る
2. 二重送信の防止：作った請求書を記録し、二度作らない。最小コードも、同じ名前のシートがあれば止まる
3. テスト用データ：最初は架空の取引先と自分のアドレスだけで試す

## 自動化の前に、締め日・端数処理・送付方法を決める

- 締め日と対象月：どの取引日の明細を、どの月の請求に入れるか
- 端数処理：消費税の1円未満を切り捨て・四捨五入・切り上げのどれにするか
- 送付方法と確認者：メールで送る取引先と、送る前に宛先・金額・添付を確かめる人

国税庁のQ&Aでは、端数処理は「一の適格請求書につき、税率ごとに1回」で、方法は任意です。出典は[国税庁「適格請求書に記載する消費税額等の端数処理」](https://www.nta.go.jp/taxes/shiraberu/zeimokubetsu/shohi/keigenzeiritsu/pdf/qa/57.pdf)で、2026-11-08に確認しました。どの方式にするかは、社内の経理責任者や税理士に確かめます。

## 最小コード：1社分の請求書シートを作る

対象月・取引先の明細を集め、税率ごとに端数を1回だけ処理して、ひな形のコピーに書き込みます。端数処理が未選択、同じシートがある、マスタにないコード、明細が0行か16行以上、税率が10%・8%以外なら、何も作らずに止まります。

```
/**
 * @OnlyCurrentDoc
 * 1社分の請求書シートを作る最小版（PDF化・メール送付はしない）v1.1 2026-11-08
 */
const TARGET_MONTH = '2026-11'; // 対象月
const TARGET_CODE = 'C-001';    // 取引先コード
const DUE_DATE = '2026年12月31日'; // 支払期限
const ROUNDING = '';            // 端数処理：「切り捨て」「四捨五入」「切り上げ」から社内のルールで選ぶ

function createOneInvoice() {
  const ss = SpreadsheetApp.getActiveSpreadsheet();
  const round = { 切り捨て: Math.floor, 四捨五入: Math.round, 切り上げ: Math.ceil }[ROUNDING];
  if (!round) throw new Error('ROUNDING に端数処理の方式を入れてください');
  const name = '請求書_' + TARGET_CODE + '_' + TARGET_MONTH;
  if (ss.getSheetByName(name)) throw new Error('「' + name + '」はもうあります（二重に作らないように止めました）');
  const client = ss.getSheetByName('取引先マスタ').getDataRange().getValues().find(r => r[0] === TARGET_CODE);
  if (!client) throw new Error('取引先マスタに ' + TARGET_CODE + ' がありません');
  const lines = ss.getSheetByName('請求明細').getDataRange().getValues().slice(1)
    .filter(r => monthOf(r[0]) === TARGET_MONTH && r[2] === TARGET_CODE);
  if (lines.length === 0 || lines.length > 15) throw new Error('明細が ' + lines.length + ' 行です（1〜15行で作れます）');
  const base = { 10: 0, 8: 0 };
  lines.forEach(r => { const t = rateOf(r[8]); if (!(t in base)) throw new Error('税率は10%か8%にしてください（' + r[5] + '）');
    base[t] += r[6] * r[7]; });                                              // 税率ごとに合計（10%・8%以外は止める）
  const tax10 = round(base[10] * 10 / 100), tax8 = round(base[8] * 8 / 100); // 端数処理は税率ごとに1回
  const f = { 取引先名: client[1], 部署: client[2], 請求書番号: 'INV-' + TARGET_MONTH.replace('-', '') + '-' + TARGET_CODE,
    発行日: new Date(), 支払期限: DUE_DATE, 対象月: TARGET_MONTH, '10%対象': base[10], '10%消費税': tax10,
    '8%対象': base[8], '8%消費税': tax8, 合計: base[10] + tax10 + base[8] + tax8 };
  const sheet = ss.getSheetByName('請求書レイアウト').copyTo(ss).setName(name);
  const range = sheet.getDataRange();
  const values = range.getValues().map(row => row.map(v => {
    if (typeof v !== 'string' || v.indexOf('{{明細:') === 0) return v;
    const one = v.match(/^\{\{([^{}]+)\}\}$/);
    if (one && one[1] in f) return f[one[1]];                                 // 1つだけなら数値・日付のまま入れる
    return v.replace(/\{\{([^{}]+)\}\}/g, (m, k) => (k in f ? f[k] : m));
  }));
  range.setValues(values);
  const top = values.findIndex(row => String(row[0]).indexOf('{{明細:') === 0) + 1; // 明細を書き始める行
  sheet.getRange(top, 1, lines.length, 6).setValues(lines.map(r =>
    [r[1], r[5], rateOf(r[8]) === 8 ? '8%※' : '10%', r[6], r[7], r[6] * r[7]]));
  ss.setActiveSheet(sheet);
}

function monthOf(v) { // 「2026-11」が日付に変わっていても読む
  return v instanceof Date ? Utilities.formatDate(v, Session.getScriptTimeZone(), 'yyyy-MM') : String(v).trim();
}
function rateOf(v) { // 「10%」は0.1と読まれるので10に直す
  const n = Number(String(v).replace('%', ''));
  return n < 1 ? Math.round(n * 100) : n;
}
```

### コードの貼り付けと実行の手順

1. 新しいスプレッドシートに「取引先マスタ」「請求明細」「請求書レイアウト」の3枚を作る
2. 取引先マスタのA1に3行を貼り、A列を選んで「データ」→「テキストを列に分割」で、区切り文字をカンマにする

```
取引先コード,取引先名,部署,メール
C-001,株式会社サンプル商事,経理部,sample-shoji@example.com
C-002,サンプル工業株式会社,総務部,sample-kogyo@example.com
```

3. 請求明細のA1にも同じ手順で5行を貼る。最後の行は前月分で、集計に入らない

```
対象月,取引日,取引先コード,取引先名,商品コード,品目,数量,単価,税率,金額
2026-11,2026/11/05,C-001,,P-01,月額保守サービス,1,33000,10%,
2026-11,2026/11/12,C-001,,P-02,作業費（1時間）,3,4500,10%,
2026-11,2026/11/19,C-001,,P-05,コーヒー豆（軽減税率）,2,1296,8%,
2026-10,2026/10/30,C-001,,P-02,前月分の作業費（集計に入らない）,1,9999,10%,
```

4. 請求書レイアウトのA1に35行を空行も含めて貼り、同じ手順で分ける。自社名などの仮の文字を直し、金額は3桁区切り、F4は日付の表示形式にする

5. 「拡張機能」→「Apps Script」を開き、最初の function myFunction() { } を消してコードを貼る。8行目を const ROUNDING = '切り捨て'; のように書き換えて保存する

2回目は「もうあります」と出て止まります。別の取引先や月は、5〜7行目を書き換えます。

### 初回の承認画面で許可する内容

自作のスクリプトでは警告が出ることがあります。詳細を開き、プロジェクト名が自分のものかを確かめてから進みます。先頭の「@OnlyCurrentDoc」は、このスプレッドシートだけを扱う権限に絞る指定です。メールやドライブの権限は求めません。出典は[Authorization for Google Services](https://developers.google.com/apps-script/guides/services/authorization)で、2026-11-08に確認しました。

- 表示される権限：【オーナー確認待ち：承認の画面に出た権限の文言】

スクリプトは、実行した人のアカウントの権限で動きます。担当が替わったら、新しい担当が承認し直します。
