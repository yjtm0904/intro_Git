## 結論：請求書の自動化は「4枚のシート」と「確かめてから送る」設計で考える

スプレッドシートで請求書を自動で作るときは、4枚のシートで考えます。取引先マスタ、請求明細、請求書のひな形、送付記録です。GAS（Google Apps Script）にさせるのは「明細を集めて、ひな形に写す」作業で、送る前に人が確かめる流れは残します。

この記事では、4枚のシートの列の構成と、1社分の請求書シートを作る48行の最小コードを載せます。PDF化とメールの送付は、この記事の範囲に入れていません。

【検証情報】検証日：2026-11-08／使ったツール：Googleスプレッドシート、Google Apps Script、Node.js 22（Googleのサービスを再現するテスト用の仕組み）
検証方法：架空の取引先2社・明細5行で最小コードのロジックをテストし、8件すべて成功（3つの端数処理の結果、前月の明細が入らないこと、2回目に止まること、記事のコードと検証に使ったコードが同じことなど）。Googleの実際の環境での確認は、筆者の【個人／Google Workspace】のアカウントで実施（確認日：【実機確認後に記入】）

## 自動化に向く請求業務・向かない請求業務

自動化の前に、自分の請求業務が向いているかを確かめます。「向く」に多く当てはまり、「向かない」に当てはまらなければ、この仕組みが使えます。

向く
- 毎月の締め日が決まっていて、毎月同じ形の請求書を作っている
- 取引先が10社以上あり、ひな形への写し間違いが心配
- 明細をスプレッドシートで管理している（または、管理できる）
- 取引先ごとの書式の違いがなく、1つのひな形で足りる
- 業務でGoogleアカウント（スプレッドシート・ドライブ・Gmail）を使える

向かない
- 会計ソフトや請求書発行サービスで、すでに請求書を出している（そちらの機能の方が早い）
- 取引先ごとに、指定の書式や提出の方法が違う
- 明細が紙やPDFで届き、まず手で入力し直す必要がある
- 勤務先がスクリプト（GAS）の利用を認めていない
- 月に数件しか請求書を作らない（手で作る方が早いことが多い）

## 全体像：取引先マスタ→請求明細→請求書→送付記録

［図解：4枚のシートとデータの流れ／取引先マスタ（宛名・メール）と請求明細（対象月・品目・数量・単価・税率）→ GASが取引先ごと・税率ごとに集計 → 請求書のひな形に写す → 人が確かめて送る → 送付記録に残す］

流れは4段階です。

1. 取引先マスタに、取引先のコード・名前・部署・メールを1社1行で登録しておく
2. 締めのあと、請求明細に明細を1件1行で入れる
3. GASが、対象月の明細を取引先ごと・税率ごとに集め、請求書のひな形に写す
4. 人が中身を確かめてから送り、送付記録に「いつ・誰に・どの請求書を」送ったかを残す

### 各シートの列の構成

列の構成は、請求書をPDFにしてメールの下書きまで作る業務パック（記事202）と同じにしています。あとから一式に広げるときも、シートを作り直さずに済みます。

取引先マスタ（1社1行）
- A列 取引先コード：例 C-001（重複させない）
- B列 取引先名：例 株式会社サンプル商事
- C列 部署：例 経理部
- D列 メール：例 sample-shoji@example.com

請求明細（明細1件で1行）
- A列 対象月：例 2026-11
- B列 取引日：例 2026/11/05
- C列 取引先コード
- D列 取引先名：表示用（取引先マスタから数式で引いてもよい）
- E列 商品コード：表示用・任意
- F列 品目
- G列 数量
- H列 単価（税抜）
- I列 税率（10% か 8%）
- J列 金額：表示用

請求書レイアウト（ひな形）
- 値を入れたい場所に {{取引先名}} のように書いておく。13行目が明細の行で、そこから15行を明細欄にする
- 自社名・住所・登録番号・振込先は、ひな形に直接書いておく

送付記録（1回送るごとに1行）
- 記録日時／モード／対象月／取引先コード／取引先名／請求書番号／合計（税込）／宛先／状態／PDFファイル名／PDFのURL／メモ

送付記録は、二重送信を防ぐための台帳です。この記事の最小コードは使いませんが、送付まで自動にするときに欠かせないので、最初から用意しておきます。

## 最小コード：1社分の請求書シートを作る

最小コードがすることは、次の4つだけです。

- 指定した取引先・対象月の明細を、請求明細から集める
- 10%と8%の対象額を合計し、それぞれに税率をかけて、端数を1回だけ処理する
- 請求書レイアウトのシートをコピーして、{{ }} の場所と明細欄に値を入れる
- 同じ取引先・同じ月のシートがすでにあれば、作らずに止まる

PDF化、メールの作成と送付、送付記録への書き込み、入力の誤りのチェックはしません。この記事のコードだけで、請求書を送れる状態にはならないことに注意してください。

```
/**
 * @OnlyCurrentDoc
 * 1社分の請求書シートを作る（最小版。PDF化・メール送付はしない）事務の型紙 107 v1.0（2026-11-08）
 */
const TARGET_MONTH = '2026-11'; // 対象月
const TARGET_CODE = 'C-001';    // 取引先コード
const DUE_DATE = '2026年12月31日'; // 支払期限
const ROUNDING = '';            // 端数処理：「切り捨て」「四捨五入」「切り上げ」から、社内のルールで選んで入れる

function createOneInvoice() {
  const ss = SpreadsheetApp.getActiveSpreadsheet();
  const round = { 切り捨て: Math.floor, 四捨五入: Math.round, 切り上げ: Math.ceil }[ROUNDING];
  if (!round) throw new Error('ROUNDING に端数処理の方式を入れてください');
  const name = '請求書_' + TARGET_CODE + '_' + TARGET_MONTH;
  if (ss.getSheetByName(name)) throw new Error('「' + name + '」はもうあります（二重に作らないように止めました）');
  const client = ss.getSheetByName('取引先マスタ').getDataRange().getValues().find(r => r[0] === TARGET_CODE);
  if (!client) throw new Error('取引先マスタに ' + TARGET_CODE + ' がありません');
  const lines = ss.getSheetByName('請求明細').getDataRange().getValues().slice(1)
    .filter(r => monthOf(r[0]) === TARGET_MONTH && r[2] === TARGET_CODE);
  if (lines.length === 0 || lines.length > 15) throw new Error('明細が ' + lines.length + ' 行です（1〜15行で作れます）');
  const base = { 10: 0, 8: 0 };
  lines.forEach(r => { base[rateOf(r[8])] += r[6] * r[7]; });               // 数量×単価を税率ごとに合計
  const tax10 = round(base[10] * 10 / 100), tax8 = round(base[8] * 8 / 100); // 端数処理は税率ごとに1回
  const f = { 取引先名: client[1], 部署: client[2], 請求書番号: 'INV-' + TARGET_MONTH.replace('-', '') + '-' + TARGET_CODE,
    発行日: new Date(), 支払期限: DUE_DATE, 対象月: TARGET_MONTH, '10%対象': base[10], '10%消費税': tax10,
    '8%対象': base[8], '8%消費税': tax8, 合計: base[10] + tax10 + base[8] + tax8 };
  const sheet = ss.getSheetByName('請求書レイアウト').copyTo(ss).setName(name);
  const range = sheet.getDataRange();
  const values = range.getValues().map(row => row.map(v => {
    if (typeof v !== 'string' || v.indexOf('{{明細:') === 0) return v;
    const one = v.match(/^\{\{([^{}]+)\}\}$/);
    if (one && one[1] in f) return f[one[1]];                                 // 1つだけなら数値・日付のまま入れる
    return v.replace(/\{\{([^{}]+)\}\}/g, (m, k) => (k in f ? f[k] : m));
  }));
  range.setValues(values);
  const top = values.findIndex(row => String(row[0]).indexOf('{{明細:') === 0) + 1; // 明細を書き始める行
  sheet.getRange(top, 1, lines.length, 6).setValues(lines.map(r =>
    [r[1], r[5], rateOf(r[8]) === 8 ? '8%※' : '10%', r[6], r[7], r[6] * r[7]]));
  ss.setActiveSheet(sheet);
}

function monthOf(v) { // 「2026-11」が日付に変わっていても読む
  return v instanceof Date ? Utilities.formatDate(v, Session.getScriptTimeZone(), 'yyyy-MM') : String(v).trim();
}
function rateOf(v) { // 「10%」のセルは 0.1 と読まれるので 10 に直す
  const n = Number(String(v).replace('%', ''));
  return n < 1 ? Math.round(n * 100) : n;
}
```

### コードの貼り付けと実行の手順

1. 新しいスプレッドシートに、4枚のシートを作る。シート名は「取引先マスタ」「請求明細」「請求書レイアウト」「送付記録」
2. 取引先マスタのA1に、次の3行を貼る。A列を選んだまま「データ」→「テキストを列に分割」（区切り文字はカンマ）を選ぶ

```
取引先コード,取引先名,部署,メール
C-001,株式会社サンプル商事,経理部,sample-shoji@example.com
C-002,サンプル工業株式会社,総務部,sample-kogyo@example.com
```

3. 請求明細のA1に、次の6行を同じ手順で貼る。最後の行は前月分で、集計に入らないことを確かめるための行

5. メニューの「拡張機能」→「Apps Script」を開き、最初からある function myFunction() { } を消して、コードを全文貼る

7. 画面の上で「createOneInvoice」を選び、「実行」を押す。初回は承認の画面が出る（次の節）
8. 「請求書_C-001_2026-11」というシートができる。端数処理が「切り捨て」なら、ご請求金額は53,949円になる

もう一度実行すると、「もうあります」と表示されて止まります。別の取引先や月で作るときは、コードの5〜7行目（対象月・取引先コード・支払期限）を書き換えます。

### 初回の承認画面で許可する内容

初めて実行すると、Googleアカウントを選ぶ画面と、スクリプトに許可する権限の一覧が出ます。自分で作ったスクリプトは、Googleの確認を受けていないため、警告の画面が出ることがあります。詳細を開いて、プロジェクト名が自分のものかを確かめてから進みます。

このコードの先頭には「@OnlyCurrentDoc」と書いてあります。Googleの公式ドキュメントによると、この指定があると、すべてのスプレッドシートではなく、このスクリプトを使っているファイルだけを扱う権限を求めます（出典：[Authorization for Google Services](https://developers.google.com/apps-script/guides/services/authorization)、確認日：2026-11-08）。メールやドライブを使わないので、それらの権限も求めません。

PDF化とメールの下書きまで進めると、Gmailとドライブの権限が加わります。Gmailの権限は、メールの閲覧や削除まで含む広い範囲になるため、何を許可するかを理解してから使うことが大切です。

## 事故を防ぐ3つの原則（下書きで確認・二重送信の防止・テスト用データ）

請求書の自動化で怖いのは、間違った金額や宛先で送ってしまうことです。仕組みを作る段階から、次の3つを守ります。

1. 下書きで確認：メールは自動で送らず、下書きを作るところまでにする。送るのは、人が1通ずつ確かめてからにする
2. 二重送信の防止：送付記録に「どの月の、どの取引先の請求書を作ったか」を残し、同じものを二度作らない。この記事の最小コードでも、同じ名前のシートがあれば止まるようにしています
3. テスト用データ：最初は架空の取引先と、自分のメールアドレスだけで試す。実在の取引先のデータで試すのは、テストが終わってからにする

AIにコードを書かせたり直させたりするときは、取引先名や金額などの実データを貼らず、コードと架空のデータだけを渡します（「生成AIに入力してはいけない情報と、マスキングのやり方」［リンク：106の記事］）。

## 自動化の前に決めること（締め日・端数処理・送付方法）

コードを書く前に、社内で次の4つを決めておきます。決まっていないと、自動化しても結局は手で直すことになります。

- 締め日と対象月：月末締めか、20日締めか。請求明細の「対象月」に、どの取引日の明細を入れるかを決める
- 端数処理：消費税の1円未満の端数を、切り捨て・四捨五入・切り上げのどれで処理するか。どれにするかは、社内の経理責任者や税理士に確かめる
- 送付方法：メールで送る取引先と、郵送や取引先のシステムへの登録が必要な取引先を分けておく
- 確認する人：送る前に、誰が何を確かめるか（宛先・金額・添付）

端数処理について、国税庁のQ&Aでは、適格請求書に書く消費税額の端数処理は「一の適格請求書につき、税率ごとに1回」とされ、処理の方法（切上げ・切捨て・四捨五入など）は任意とされています（出典：[国税庁「適格請求書に記載する消費税額等の端数処理」](https://www.nta.go.jp/taxes/shiraberu/zeimokubetsu/shohi/keigenzeiritsu/pdf/qa/57.pdf)、確認日：2026-11-08）。この記事の最小コードも、税率ごとに1回だけ端数を処理しています。どの方式を選ぶべきかは、この記事では判断しません。

送付の文面を先に整えたい場合は、「請求書の送付・入金確認メール文例」（［リンク：108の記事］）が使えます。

## まとめ：PDF化とメール送付まで一式にした業務パック

請求書の自動化は、取引先マスタ・請求明細・請求書のひな形・送付記録の4枚で考えます。最小コードで1社分の請求書シートを作れたら、次は全社分をまとめて作り、PDFにして送る段階です。

PDF化、メールの下書き、送付記録、テストモード、二重送信の防止までを一式にした有料の業務パック（GAS請求書パック）を、12月上旬に公開する予定です。列の構成はこの記事と同じなので、ここで作ったシートをそのまま使えます。公開後、ここにリンクを追記します。

請求明細のD列に、取引先マスタから取引先名を引く数式の頼み方は、VLOOKUP・XLOOKUPをAIに書かせる記事で扱う予定です（公開後にリンクを追記します）。
