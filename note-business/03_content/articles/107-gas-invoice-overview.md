## 結論：請求書の自動化は「4枚のシート」と「確かめてから送る」設計で考える

Googleスプレッドシートで請求書を自動で作るときは、取引先マスタ・請求明細・請求書のひな形・送付記録の4枚で考えます。GAS（Google Apps Script）にさせるのは明細を集めてひな形に写す作業で、送る前に人が確かめる流れは残します。この記事では、列の構成と、1社分の請求書シートを作る49行の最小コードを載せます（PDF化とメールの送付は扱いません）。

【検証情報】検証日：2026-11-08／使ったツール：Googleスプレッドシート、Google Apps Script、Node.js 22（Googleのサービスを再現するテスト用の仕組み）
検証方法：架空の取引先2社・明細5行で最小コードをテストし、9件すべて成功（端数処理の3方式、税率の誤りで止まること、2回目に止まることなど）。Googleの実際の環境での確認は【オーナー確認待ち：実機確認の日付とアカウントの種類（個人／Google Workspace）】

## 自動化に向く請求業務・向かない請求業務

向く
- 締め日が決まっていて、毎月同じ形の請求書を作る
- 取引先が10社以上あり、写し間違いが心配
- 明細をスプレッドシートで管理できる

向かない
- 会計ソフトや請求書発行サービスで発行している（その機能の方が早い）
- 取引先ごとに書式や提出の方法が違う
- 1社の明細が月に16行以上ある（ひな形の明細欄は15行）
- 業務でGoogleアカウントを使えない、または勤務先がスクリプト（GAS）を認めていない

## 全体像：取引先マスタ→請求明細→請求書→送付記録

［図解：4枚のシートとデータの流れ／取引先マスタと請求明細 → GASが取引先ごと・税率ごとに集計 → 請求書のひな形に写す → 人が確かめて送る → 送付記録に残す］

締めのあと、請求明細に明細を1件1行で入れます。GASが対象月の明細を取引先ごと・税率ごとに集めてひな形に写し、人が確かめてから送ります。

### 各シートの列の構成

列は有料の「GAS請求書パック」と同じなので、ここで作ったシートをそのまま使えます。

- 取引先マスタ：A 取引先コード（重複させない）／B 取引先名／C 部署／D メール
- 請求明細：A 対象月／B 取引日／C 取引先コード／D 取引先名（表示用）／E 商品コード（任意）／F 品目／G 数量／H 単価（税抜）／I 税率（10%か8%）／J 金額（表示用）
- 請求書レイアウト：値を入れたい場所に {{取引先名}} のように書く。13行目から15行が明細欄。自社名や振込先は直接書く
- 送付記録：送付まで自動にするときに使う、二重送信を防ぐ台帳（GAS請求書パックで扱う）

## 事故を防ぐ3つの原則（下書きで確認・二重送信の防止・テスト用データ）

1. 下書きで確認：メールは下書きまでにし、人が確かめてから送る
2. 二重送信の防止：作った請求書を記録し、同じものを二度作らない（最小コードも、同じ名前のシートがあれば止まる）
3. テスト用データ：最初は架空の取引先と自分のアドレスだけで試す

AIにコードを直してもらうときは、取引先名や金額などの実データは貼らず、コードと架空のデータだけを渡します（［リンク：106の記事］）。

## 自動化の前に決めること（締め日・端数処理・送付方法）

- 締め日と対象月：どの取引日の明細を、どの月の請求に入れるか
- 端数処理：消費税の1円未満を切り捨て・四捨五入・切り上げのどれにするか（社内の経理責任者や税理士に確かめる）
- 送付方法と確認する人：メールで送る取引先を分け、送る前に誰が宛先・金額・添付を確かめるか

国税庁のQ&Aでは、適格請求書の消費税額の端数処理は「一の適格請求書につき、税率ごとに1回」、方法は任意とされています（出典：[国税庁「適格請求書に記載する消費税額等の端数処理」](https://www.nta.go.jp/taxes/shiraberu/zeimokubetsu/shohi/keigenzeiritsu/pdf/qa/57.pdf)、確認日：2026-11-08）。最小コードも税率ごとに1回だけ処理します。どの方式を選ぶべきかは判断しません。

## 最小コード：1社分の請求書シートを作る

指定した取引先・対象月の明細を集め、10%と8%の対象額ごとに端数を1回だけ処理し、ひな形をコピーしたシートに値を入れます。端数処理を選んでいない、同じシートがある、マスタにないコード、明細が0行か16行以上、税率が10%・8%以外（品目名を表示）のときは、何も作らずに止まります。PDF化とメールの作成はしません。

```
/**
 * @OnlyCurrentDoc
 * 1社分の請求書シートを作る（最小版。PDF化・メール送付はしない）事務の型紙 107 v1.1（2026-11-08）
 */
const TARGET_MONTH = '2026-11'; // 対象月
const TARGET_CODE = 'C-001';    // 取引先コード
const DUE_DATE = '2026年12月31日'; // 支払期限
const ROUNDING = '';            // 端数処理：「切り捨て」「四捨五入」「切り上げ」から、社内のルールで選んで入れる

function createOneInvoice() {
  const ss = SpreadsheetApp.getActiveSpreadsheet();
  const round = { 切り捨て: Math.floor, 四捨五入: Math.round, 切り上げ: Math.ceil }[ROUNDING];
  if (!round) throw new Error('ROUNDING に端数処理の方式を入れてください');
  const name = '請求書_' + TARGET_CODE + '_' + TARGET_MONTH;
  if (ss.getSheetByName(name)) throw new Error('「' + name + '」はもうあります（二重に作らないように止めました）');
  const client = ss.getSheetByName('取引先マスタ').getDataRange().getValues().find(r => r[0] === TARGET_CODE);
  if (!client) throw new Error('取引先マスタに ' + TARGET_CODE + ' がありません');
  const lines = ss.getSheetByName('請求明細').getDataRange().getValues().slice(1)
    .filter(r => monthOf(r[0]) === TARGET_MONTH && r[2] === TARGET_CODE);
  if (lines.length === 0 || lines.length > 15) throw new Error('明細が ' + lines.length + ' 行です（1〜15行で作れます）');
  const base = { 10: 0, 8: 0 };
  lines.forEach(r => { const t = rateOf(r[8]); if (!(t in base)) throw new Error('税率は10%か8%にしてください（' + r[5] + '）');
    base[t] += r[6] * r[7]; });                                              // 数量×単価を税率ごとに合計（10%・8%以外は止める）
  const tax10 = round(base[10] * 10 / 100), tax8 = round(base[8] * 8 / 100); // 端数処理は税率ごとに1回
  const f = { 取引先名: client[1], 部署: client[2], 請求書番号: 'INV-' + TARGET_MONTH.replace('-', '') + '-' + TARGET_CODE,
    発行日: new Date(), 支払期限: DUE_DATE, 対象月: TARGET_MONTH, '10%対象': base[10], '10%消費税': tax10,
    '8%対象': base[8], '8%消費税': tax8, 合計: base[10] + tax10 + base[8] + tax8 };
  const sheet = ss.getSheetByName('請求書レイアウト').copyTo(ss).setName(name);
  const range = sheet.getDataRange();
  const values = range.getValues().map(row => row.map(v => {
    if (typeof v !== 'string' || v.indexOf('{{明細:') === 0) return v;
    const one = v.match(/^\{\{([^{}]+)\}\}$/);
    if (one && one[1] in f) return f[one[1]];                                 // 1つだけなら数値・日付のまま入れる
    return v.replace(/\{\{([^{}]+)\}\}/g, (m, k) => (k in f ? f[k] : m));
  }));
  range.setValues(values);
  const top = values.findIndex(row => String(row[0]).indexOf('{{明細:') === 0) + 1; // 明細を書き始める行
  sheet.getRange(top, 1, lines.length, 6).setValues(lines.map(r =>
    [r[1], r[5], rateOf(r[8]) === 8 ? '8%※' : '10%', r[6], r[7], r[6] * r[7]]));
  ss.setActiveSheet(sheet);
}

function monthOf(v) { // 「2026-11」が日付に変わっていても読む
  return v instanceof Date ? Utilities.formatDate(v, Session.getScriptTimeZone(), 'yyyy-MM') : String(v).trim();
}
function rateOf(v) { // 「10%」のセルは 0.1 と読まれるので 10 に直す
  const n = Number(String(v).replace('%', ''));
  return n < 1 ? Math.round(n * 100) : n;
}
```

### コードの貼り付けと実行の手順

1. 新しいスプレッドシートに「取引先マスタ」「請求明細」「請求書レイアウト」「送付記録」の4枚を作る
2. 取引先マスタのA1に次の3行を貼り、A列を選んで「データ」→「テキストを列に分割」（区切り文字はカンマ）

```
取引先コード,取引先名,部署,メール
C-001,株式会社サンプル商事,経理部,sample-shoji@example.com
C-002,サンプル工業株式会社,総務部,sample-kogyo@example.com
```

3. 請求明細のA1にも同じ手順で6行を貼る（最後の行は前月分で、集計に入らない）

```

```

5. 「拡張機能」→「Apps Script」で、最初の function myFunction() { } を消してコードを貼る。8行目を const ROUNDING = '切り捨て'; のように書き換えて保存する

もう一度実行すると「もうあります」と出て止まります。別の取引先や月は、コードの5〜7行目を書き換えます。

### 初回の承認画面で許可する内容

自分で作ったスクリプトは、Googleの確認を受けていないため警告の画面が出ることがあります。詳細を開き、プロジェクト名が自分のものかを確かめてから進みます。先頭の「@OnlyCurrentDoc」は、このスプレッドシートだけを扱う権限に絞る指定で、メールやドライブの権限は求めません（出典：[Authorization for Google Services](https://developers.google.com/apps-script/guides/services/authorization)、確認日：2026-11-08）。

- 承認の画面に表示される権限：【オーナー確認待ち：承認の画面に表示された権限の文言】

スクリプトは、実行した人のアカウントの権限で動きます。担当が替わったら、新しい担当が承認し直します。

## まとめ：PDF化とメール送付まで一式にした業務パック

全社分のPDFとメールの下書きまで進めると、次のことが変わります。

- 取引先と月を書き換えずに、全社分をまとめて作れる
- PDFの保存、Gmailの下書き、送付記録による二重送信の防止まで行う
- テストモードで、宛先をすべて自分にして試せる

この一式は、有料の「GAS請求書パック」として12月上旬に公開する予定です（公開後にリンクを追記します）。送付の文面は「請求書の送付・入金確認メール文例」（［リンク：108の記事］）にあります。
