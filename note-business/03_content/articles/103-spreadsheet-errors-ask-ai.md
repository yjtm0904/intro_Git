## 結論：AIには「数式・データの例・期待した結果」の3点を渡す

ExcelやGoogleスプレッドシートでエラーが出たときは、AIに「数式」「データの例」「期待した結果」の3点を渡して相談します。エラーの表示（#N/Aなど）だけを伝えると、考えられる原因が多すぎて、答えが一般論になりがちです。

この記事では、そのまま使える相談テンプレートと、事務の表でよく出るエラー7種の原因・確かめ方・直し方を載せます。エラーが出ないのに合計が合わない、という見つけにくいずれも扱います。

【検証情報】検証日：2026-11-08／使ったツール：Claude（2026年11月時点）、LibreOffice Calc 24.2、Python 3.13
検証方法：架空の取引先マスタ10社・請求明細20行でエラー6種を実際に起こし（#REF!は列を実際に削除して再現）、修正前後の値をPythonで求めた期待値と照合（57セルすべて一致）。相談テンプレートでClaudeに7種を相談し、返ってきた修正の式も検算した。配列のエラーはこの環境で再現できないため、Excel（Microsoft 365）とスプレッドシートで表示を確認（確認日：【実機確認後に記入】）

## AIに貼る相談テンプレート

次のテンプレートの（ ）を埋めて、AIに貼ります。数式は、セルからそのままコピーします。

```
次の数式で困っています。原因と直し方を教えてください。

【やりたいこと】
（例：請求明細のD列に、C列の取引先コードに対応する取引先名を表示したい）

【数式】
（例：D4：=VLOOKUP(C4,取引先マスタ!$A$2:$D$11,2,FALSE)）

【サンプル】（列名とダミー値）
（例：取引先マスタ（A2:D11）：A列 取引先コード（C-001〜C-010）、B列 取引先名
 請求明細：C4 取引先コード「C-003」（CSVから貼り付けた）。ほかの行は社名が出ている）

【期待した結果】
（例：株式会社見本デザイン）

【実際の表示】
（例：#N/A）

【使っているソフトと版】
（例：Microsoft 365のExcel）

【出してほしいもの】
考えられる原因を可能性の高い順に3つまで、それぞれの確かめ方、直した数式
```

上の例のとおりに埋めて相談したときの出力例です（抜粋。太字の記号などは省いています）。

```
他の行は正しく表示され、C4だけがCSVから貼り付けた値です。そのため、C4の文字列がマスタの「C-003」と見た目は同じでも、中身が違う可能性が高いです。数式そのものに誤りはありません。
（中略）
① 前後に空白が付いている（通常の空白、またはノーブレークスペース）
CSVの値は「C-003 」のように、末尾に空白が付いていることがよくあります。
- 確かめ方：=LEN(C4) が 5より大きいかどうか。
（中略）
VLOOKUPのままで済ませたい場合、原因が①だけなら次の数式で足ります。
=VLOOKUP(TRIM(SUBSTITUTE(C4,CHAR(160)," ")),取引先マスタ!$A$2:$D$11,2,FALSE)
```

出力例はClaudeで生成しています。AIの出力は毎回少しずつ変わります。検証では、C4の後ろに空白を入れておいたので、第1候補が当たりました。返ってきた式も、検算で正しい社名になりました。ChatGPT・Gemini・Copilotでも同じ形で相談できますが、筆者が出力を確かめたのはClaudeだけです。

### 渡す情報と、渡さない情報（実データは置き換える）

渡すのは、数式、列名と例の値、期待した結果、実際の表示、ソフトと版です。会社のファイルを丸ごと貼ったり、画面をそのまま撮って貼ったりはしません。

- 取引先名・人の名前：「株式会社サンプル商事」「担当者A」のような架空の名前に置き換える
- メールアドレス：sample@example.com のような例示用のアドレスにする
- 金額：桁と形（文字か数値か）が分かれば、実際の金額でなくてよい
- 取引先コード・商品コード：形が同じ架空のコード（C-001など）にする

置き換え方と、AIに入れてはいけない情報の一覧は、「生成AIに入力してはいけない情報と、マスキングのやり方」（［リンク：106の記事］）にまとめています。勤務先のAI利用ルールも先に確かめてください。

## エラー別の原因と直し方

7種とも、同じ架空の表で起こして確かめました。表の列は、取引先マスタ（A 取引先コード／B 取引先名など）と、請求明細（C 取引先コード／E 商品コード／G 数量／H 単価／J 金額など）です。7種とも、相談テンプレートで聞いたときの第1候補は、仕込んだ原因と同じでした。

### #N/A：探す値が見つからない

- 原因：探す値が、探す範囲にありません。見た目は同じでも、後ろの空白や全角のハイフンで、違う値になっていることがよくあります（CSVから貼った値など）
- 確かめ方：=LEN(C4) で文字数を見ます。「C-003」は5文字ですが、検証の表では6でした。=C4="C-003" がFALSEなら、中身が違います
- 修正前：=VLOOKUP(C4,取引先マスタ!$A$2:$D$11,2,FALSE) → #N/A
- 修正後：=VLOOKUP(TRIM(C4),取引先マスタ!$A$2:$D$11,2,FALSE) → 株式会社見本デザイン
- 相談例の要点：「見た目は同じ」「CSVから貼った」「ほかの行は出ている」と書くと、候補が絞られました。AIは、式で補うより貼り付けた列そのものを直すことも勧めました

VLOOKUP・XLOOKUPの書き方そのものは、「VLOOKUP・XLOOKUPをAIに書かせる頼み方」（［リンク：105の記事］）で扱っています。

### #VALUE!：文字と数値が混ざっている

- 原因：計算に使うセルに、数値にできない文字が入っています（「5個」「未定」など）
- 確かめ方：=ISNUMBER(G7) がFALSEなら、G7は文字です
- 修正前：=G7*H7 → #VALUE!（G7が「5個」）
- 修正後：G7を「5」に直すと、元の式のまま4320。「個」を表示したいときは、表示形式（ユーザー定義）を 0"個" にします（AIの提案）。データを直せないときは =VALUE(SUBSTITUTE(G7,"個",""))*H7 → 4320
- 相談例の要点：AIは、式で吸収するよりデータを直す方法を先に挙げました

### #REF!：参照先の行や列を消した

- 原因：数式が参照していた行・列・シートを削除しました。数式の中の参照が #REF! に置き換わります
- 確かめ方：数式バーに #REF! が書かれているかを見ます。検証では、H列（単価）を削除すると、金額の式 =G2*H2 が #REF! になりました。金額の列も、J列からI列へ1つ左にずれます
- 直し方：削除した直後なら、まずCtrl+Z（元に戻す）で戻します。戻せないときは、参照を入れ直します。単価を消した場合は、商品マスタから引く式で作り直せます
- 修正後：=G2*VLOOKUP(E2,商品マスタ!$A$2:$D$11,3,FALSE) → 33000
- 相談例の要点：AIは、マスタから単価を引く形にすると、マスタの単価を変えたときに過去の明細の金額も変わる、と注意しました。計算したら値として貼り付けて固定します

### #DIV/0!：0や空白で割っている

- 原因：0か空欄のセルで割っています。空欄は、割り算では0として扱われます
- 確かめ方：割る数のセル（B5）が0か空欄かを見ます
- 修正前：=C5/B5 → #DIV/0!（前月比。C-004は前月が0、C-005は前月が空欄）
- 修正後：=IF(B5=0,"",C5/B5) → 前月が0か空欄の行は空欄、ほかの行は前月比
- 相談例の要点：スプレッドシートで相談したところ、=IF(N(B5)=0,"",C5/B5) などが返り、検算で同じ結果になりました。=IFERROR(C5/B5,"") でも空欄にはなりますが、ほかのエラーも隠れる、とAIも注意しています

### #NAME?：関数名の誤り・Excelの版の違い

- 原因：関数名の打ち間違い（VLOOKUPPなど）か、使っている版にない関数です。XLOOKUPはExcel 2016・2019では使えません（出典：[Microsoft サポート「XLOOKUP 関数」](https://support.microsoft.com/ja-jp/excel/functions/xlookup-function)、確認日：2026-11-08）
- 確かめ方：関数名のつづりを見ます。同僚のファイルで出たときは、自分と同僚の版を比べます。検証に使ったLibreOffice 24.2でも、XLOOKUPは #NAME? になりました
- 修正前：=XLOOKUP(C2,取引先マスタ!$A$2:$A$11,取引先マスタ!$B$2:$B$11,"未登録") → #NAME?（Excel 2019）
- 修正後：=IFNA(INDEX(取引先マスタ!$B$2:$B$11,MATCH(C2,取引先マスタ!$A$2:$A$11,0)),"未登録") → 株式会社サンプル商事
- 相談例の要点：AIは確かめ方として、数式バーで関数名の前に「_xlfn.」が付いているかを見る方法も挙げました（筆者はExcel 2019の画面では確かめていません）

### 配列が展開できない（Excelの#SPILL!・スプレッドシートの#REF!）

- 原因：UNIQUE・FILTER・SORTのように、結果を複数のセルに広げる式で、広げる先のセルに文字などが入っています
- 例：F2の =UNIQUE(請求明細!C2:C21) は、F2からF11へ10個の取引先コードを広げます。F5に「メモ：要確認」があると広げられません
- Excel：#SPILL! と表示されます。エラーのセルを選ぶと広げる予定の範囲が示され、邪魔をしているセルを選ぶ機能もあります（出典：[Microsoft サポート「#SPILL! エラーを修正する方法」](https://support.microsoft.com/ja-jp/excel/how-to-correct-a-spill-error)、確認日：2026-11-08）
- スプレッドシート：#REF! と表示され、セルにカーソルを合わせると理由の説明が出ます。表示の文言は画面で確かめてください（配列の仕組み：[Google ドキュメント エディタ ヘルプ「Google スプレッドシートで配列を使用する」](https://support.google.com/docs/answer/6208276?hl=ja)、確認日：2026-11-08）
- 直し方：邪魔をしているセル（F5）の文字を、別の列へ移すか消します。F2〜F11に10個が並びます（検証に使ったLibreOffice 24.2はUNIQUEに対応していないため、Excelとスプレッドシートで確認：【実機確認後に記入】）
- 相談例の要点：AIはF5を第1候補に挙げ、ほかに、見えない入力・結合セル・テーブルの中に式がある場合を候補にしました

### エラーは出ないのに合計が合わない

- 原因：数値に見える文字（CSVから貼った金額など）は、SUMが黙って飛ばします。エラーにならないので、気づきにくいずれです
- 確かめ方：=COUNT(J2:J21) が行数（20）より少なければ、文字のセルがあります。検証の表では18でした。=COUNTA(J2:J21)-COUNT(J2:J21) で、文字のセルの数（2）が分かります
- 修正前：=SUM(J2:J21) → 160,055（電卓で足した値は162,015）
- 修正後：作業列に =VALUE(J2) を入れて下までコピーし、値として貼り付けて元の列に戻すと、=SUM(J2:J21) は162,015
- 相談例の要点：AIは、文字のセルだけを合計する式で差額（1,960）を確かめる方法と、計算方法が「手動」になっている場合も候補に挙げました

## AIの修正案を確かめる3つの手順

AIの修正案は、そのまま全行に広げずに、次の3つで確かめます。検証で返ってきた式は、検算できたものはすべて正しい値になりました。それでも、自分の表で確かめる手順は省きません。

1. 原因を確かめてから直す：AIが挙げた確かめ方（LEN・ISNUMBER・COUNTなど）で、原因が本当にそれかを見ます。当たっていなければ、確かめた結果を書き足して相談し直します
2. エラーの行と、正しかった行の両方で試す：直した式を下の行までコピーし、正しく出ていた行、端の行、空欄の行、マスタにないコードの行でも試します
3. 期待した結果と、版を確かめる：電卓の合計やマスタの値と照らし合わせます。Microsoft 365と書いて相談すると、365でしか動かない関数（LET・XLOOKUPなど）を使った式も返ってきました。ほかの版の人とファイルを共有するときは、その版で動く式を頼み直します
