## 結論：AIには「数式・データの例・期待した結果」の3点を渡す

ExcelやGoogleスプレッドシートでエラーが出たときは、AIに「数式」「データの例」「期待した結果」の3点を渡して相談します。エラーの表示（#N/Aなど）だけでは原因の候補が多すぎて、答えが一般論になりがちです。この記事では、そのまま使える相談テンプレートと、事務の表でよく出るエラー7種の原因・確かめ方・直し方を載せます。

エラーの表示から探す：#N/A（見つからない）／#VALUE!（文字が混ざる）／#REF!（参照先を消した）／#DIV/0!（0や空欄で割る）／#NAME?（関数名・版）／#SPILL!など（結果を広げられない）／エラーなしで合計がずれる。なお、Excelの「#####」は列の幅が足りないだけで、エラーではありません。

【検証情報】検証日：2026-11-08／使ったツール：Claude（2026年11月時点）、LibreOffice Calc 24.2、Python 3.13
検証方法：架空の取引先マスタ10社・請求明細20行でエラー6種を実際に起こし（#REF!は列を実際に削除して再現）、修正前後の値をPythonで求めた期待値と照合（57セルすべて一致）。相談テンプレートでClaudeに7種を各2回相談し（2回とも第1候補は仕込んだ原因と同じ）、1回目に返ってきた修正の式を検算した。結果を広げられないエラーはこの環境で再現できないため、表示はMicrosoftとGoogleのヘルプによる（実機での確認は【オーナー確認待ち：Excel（Microsoft 365）とスプレッドシートでの確認日】）

## AIに貼る相談テンプレート

次のテンプレートの（ ）を埋めて、AIに貼ります。数式は、セルからそのままコピーします。

```
次の数式で困っています。原因と直し方を教えてください。

【やりたいこと】
（例：請求明細のD列に、C列の取引先コードに対応する取引先名を表示したい）

【数式】
（例：D4：=VLOOKUP(C4,取引先マスタ!$A$2:$D$11,2,FALSE)）

【サンプル】（列名とダミー値）
（例：取引先マスタ（A2:D11）：A列 取引先コード（C-001〜C-010）、B列 取引先名
 請求明細：C4 取引先コード「C-003」（CSVから貼り付けた）。ほかの行は社名が出ている）

【期待した結果】
（例：株式会社見本デザイン）

【実際の表示】
（例：#N/A）

【使っているソフトと版】
（例：Microsoft 365のExcel）

【出してほしいもの】
考えられる原因を可能性の高い順に3つまで、それぞれの確かめ方、直した数式
```

上の例のとおりに埋めて相談したときの出力例です（抜粋。太字の記号などは省いています）。

```
（前略）C4の文字列がマスタの「C-003」と見た目は同じでも、中身が違う可能性が高いです。数式そのものに誤りはありません。
（中略）
① 前後に空白が付いている（通常の空白、またはノーブレークスペース）
CSVの値は「C-003 」のように、末尾に空白が付いていることがよくあります。
- 確かめ方：=LEN(C4) が 5より大きいかどうか。
（中略）
VLOOKUPのままで済ませたい場合、原因が①だけなら次の数式で足ります。
=VLOOKUP(TRIM(SUBSTITUTE(C4,CHAR(160)," ")),取引先マスタ!$A$2:$D$11,2,FALSE)
```

出力例はClaudeで生成しています。AIの出力は毎回少しずつ変わります。Claudeで検証しました。ChatGPT・Gemini・Copilotでも同じ依頼文を使えますが、出力は異なります（未検証）。

### 渡す情報と、渡さない情報（実データは置き換える）

渡すのは、数式、列名と例の値、期待した結果、実際の表示、ソフトと版、それに気づいたこと（どこから貼ったか、直前にした操作）です。AIに入れない情報は次の3つです。

- 取引先名・人の名前・メールアドレスの実際の値
- 金額・口座番号などの実データ
- 会社のファイルそのもの（丸ごとの貼り付けや、画面の撮影）

置き換え例：実在の社名は「株式会社サンプル商事」、アドレスは「sample@example.com」にします。詳しくは「生成AIに入力してはいけない情報と、マスキングのやり方」（［リンク：106の記事］）にあります。勤務先のAI利用ルールも先に確かめてください。

## エラー別の原因と直し方

7種とも、同じ架空の表（取引先マスタと、C 取引先コード／G 数量／H 単価／J 金額などの請求明細）で起こしました。相談文に気づいたこと（「CSVから貼った」「H列を削除したら」など）を書いたので、7種とも第1候補に仕込んだ原因が挙がりました（各2回。テンプレートなしの相談とは比べていません）。

### #N/A：探す値が見つからない

- 原因：探す値が探す範囲にありません。見た目は同じでも、後ろの空白や全角のハイフンで違う値になっていることがよくあります（CSVから貼った値など）
- 確かめ方：=LEN(C4) で文字数を見ます（「C-003」は5文字。検証の表では6）。=C4="C-003" がFALSEなら中身が違います
- 修正前の =VLOOKUP(C4,取引先マスタ!$A$2:$D$11,2,FALSE) は #N/A。次の式で「株式会社見本デザイン」になります

```
=VLOOKUP(TRIM(C4),取引先マスタ!$A$2:$D$11,2,FALSE)
```

- 相談の要点：「見た目は同じ」「CSVから貼った」と書くと候補が絞られ、AIは貼った列そのものを直すことも勧めました

VLOOKUP・XLOOKUPの書き方は、「VLOOKUP・XLOOKUPをAIに書かせる頼み方」（［リンク：105の記事］）で扱っています。

### #VALUE!：文字と数値が混ざっている

- 原因：計算に使うセルに、数値にできない文字（「5個」「未定」など）が入っています
- 確かめ方：=ISNUMBER(G7) がFALSEなら、G7は文字です
- 直し方：G7を「5」に直すと、元の =G7*H7 のまま4320。「個」を見せたいときは、表示形式（ユーザー定義）を 0"個" にします（AIの提案）。データを直せないときは、次の式で4320になります

```
=VALUE(SUBSTITUTE(G7,"個",""))*H7
```

- 相談の要点：AIは、式で補うよりデータを直す方法を先に挙げました

### #REF!：参照先の行や列を消した

- 原因：数式が参照していた行・列・シートを削除しました。数式の中の参照が #REF! に置き換わります
- 確かめ方：数式バーに #REF! が書かれているかを見ます。検証では、H列（単価）の削除で =G2*H2 が #REF! になり、金額の列もI列へずれました
- 直し方：削除した直後なら、まずCtrl+Z（元に戻す）で戻します。スプレッドシートは「ファイル」→「変更履歴」から、削除する前の版に戻すこともできます。単価を消した場合は、商品マスタから引く式で作り直せます（33000）

```
=G2*VLOOKUP(E2,商品マスタ!$A$2:$D$11,3,FALSE)
```

- 注意：マスタから単価を引く形にすると、マスタの単価を変えたときに過去の明細の金額も変わります。計算したら、値として貼り付けて固定します（AIの指摘）

### #DIV/0!：0や空白で割っている

- 原因：0か空欄のセルで割っています。空欄は、割り算では0として扱われます
- 確かめ方：割る数のセル（B5）が0か空欄かを見ます
- 修正前の前月比 =C5/B5 は #DIV/0!（C-004は前月が0、C-005は空欄）。次の式で、前月が0か空欄の行は空欄、ほかの行は前月比になります

```
=IF(B5=0,"",C5/B5)
```

- 相談の要点：スプレッドシートでの相談では =IF(N(B5)=0,"",C5/B5) などが返り、検算で同じ結果でした。=IFERROR(C5/B5,"") はほかのエラーも隠す、とAIも注意しています

### #NAME?：関数名の誤り・Excelの版の違い

- 原因：関数名の打ち間違い（VLOOKUPPなど）か、使っている版にない関数です。XLOOKUPはExcel 2016・2019では使えません（出典：[Microsoft サポート「XLOOKUP 関数」](https://support.microsoft.com/ja-jp/excel/functions/xlookup-function)、確認日：2026-11-08）
- 確かめ方：関数名のつづりと、自分と相手の版を見ます。検証に使ったLibreOffice 24.2でも #NAME? でした
- Excel 2019では =XLOOKUP(C2,取引先マスタ!$A$2:$A$11,取引先マスタ!$B$2:$B$11,"未登録") が #NAME?。次の式に書き換えると「株式会社サンプル商事」になります

```
=IFNA(INDEX(取引先マスタ!$B$2:$B$11,MATCH(C2,取引先マスタ!$A$2:$A$11,0)),"未登録")
```

- 相談の要点：AIは確かめ方として、数式バーで関数名の前に「_xlfn.」が付いているかを見る方法も挙げました（筆者はExcel 2019の画面では確かめていません）

### 配列が展開できない（Excelの#SPILL!・スプレッドシートの#REF!）

- 原因：UNIQUE・FILTER・SORTのように結果を複数のセルに広げる式で、広げる先に値があります。これらの関数は、Microsoft 365・Excel 2021以降とスプレッドシートで使えます
- 例：F2の =UNIQUE(請求明細!C2:C21) は、F2〜F11に10個の取引先コードを広げます。F5に「メモ：要確認」があると広げられません
- Excel：#SPILL! になります。エラーのセルを選ぶと広げる予定の範囲が示され、邪魔をしているセルを選ぶ機能もあります（出典：[Microsoft サポート「#SPILL! エラーを修正する方法」](https://support.microsoft.com/ja-jp/excel/how-to-correct-a-spill-error)、確認日：2026-11-08）
- スプレッドシート：#REF! になり、セルにカーソルを合わせると理由が表示されます（配列の仕組み：[Google ドキュメント エディタ ヘルプ「Google スプレッドシートで配列を使用する」](https://support.google.com/docs/answer/6208276?hl=ja)、確認日：2026-11-08）
- 直し方：邪魔をしているセル（F5）の文字を移すか消すと、F2〜F11に10個が並びます。ここまでの表示は両社のヘルプによるもので、実機での確認は【オーナー確認待ち：ExcelとスプレッドシートでF5を消したあとの表示】
- 相談の要点：AIはF5を第1候補に挙げ、ほかに見えない入力・結合セル・テーブルの中を候補にしました

### エラーは出ないのに合計が合わない

- 原因：数値に見える文字（CSVから貼った金額など）は、SUMが黙って飛ばします
- 確かめ方：=COUNT(J2:J21) が行数（20）より少なければ、文字のセルがあります（検証では18）。=COUNTA(J2:J21)-COUNT(J2:J21) で、文字のセルの数（2）が分かります
- 修正前の =SUM(J2:J21) は160,055（電卓では162,015）。作業列に次の式を入れて下までコピーし、値として貼り付けて元の列に戻すと、=SUM(J2:J21) は162,015になります

```
=VALUE(J2)
```

- 相談の要点：AIは、文字のセルだけを合計して差額（1,960）を確かめる方法と、計算方法が「手動」になっている場合も候補に挙げました

## AIの修正案を確かめる3つの手順

AIの修正案は、全行に広げる前に次の3つで確かめます（検証で返ってきた式は、検算できたものはすべて正しい値）。

1. 原因を確かめてから直す：AIが挙げた確かめ方（LEN・ISNUMBER・COUNTなど）で、原因が本当にそれかを見る。違えば、確かめた結果を書き足して相談し直す
2. エラーの行と、正しかった行の両方で試す：直した式を下の行までコピーし、正しく出ていた行、端の行、空欄の行、マスタにないコードの行でも試す
3. 期待した結果と、版を確かめる：電卓の合計やマスタの値と照らし合わせる。AIの式には、Excel 2019以前では動かない関数（LET・XLOOKUPや、結果を広げる配列の式など。使えるのはMicrosoft 365とExcel 2021以降）が入ることがある。ほかの版の人とファイルを共有するときは、その版で動く式を頼み直す（出典：[Microsoft サポート「What's new in Excel 2021 for Windows」](https://support.microsoft.com/en-us/excel/what-s-new-in-excel-2021-for-windows)、確認日：2026-11-08）
