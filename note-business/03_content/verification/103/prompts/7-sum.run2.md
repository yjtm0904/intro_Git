# J22が1,960少なくなる原因と直し方

エラーが出ずに合計だけ少ない場合、**SUMが一部のセルを数値として数えていない**か、**画面の表示と実際の値が違う**ことがほとんどです。可能性の高い順に3つ挙げます。

---

## 原因1：一部の金額が「文字列」になっている（最も可能性が高い）

CSVを貼り付けると、見た目は数字でも中身が文字列になることがあります。SUMは文字列を**エラーを出さずに無視**します。今回の症状に一番よく当てはまります。

よくあるパターンは次のとおりです。
- 前後に空白がある（ノーブレークスペース CHAR(160) を含む）
- 全角数字になっている（例：「１９６０」）
- `"1,960"` のように、カンマ付きの文字列として取り込まれた

**確かめ方**
1. J2:J21を選択し、画面右下のステータスバーを見ます。「データの個数」と「数値の個数」が違えば、文字列が混ざっています。
2. 空いているセルに次の数式を入れます。
   ```
   =SUMPRODUCT(--ISTEXT(J2:J21))
   ```
   文字列になっているセルの数が返ります。
3. 文字列のセルの合計が1,960かどうかを確かめます。
   ```
   =SUM(IFERROR(--ASC(TRIM(SUBSTITUTE(J2:J21,CHAR(160),""))),0))-SUM(J2:J21)
   ```
   結果が1960なら、これが原因です。
4. 該当セルには、左上に緑の三角が出ていることが多いです。また、数字が左寄せで表示されていれば文字列の可能性が高いです。

**直した数式（J22）**
```
=SUM(IFERROR(--ASC(TRIM(SUBSTITUTE(J2:J21,CHAR(160),""))),0))
```
各関数の役割は次のとおりです。
- `SUBSTITUTE(…,CHAR(160),"")`：ノーブレークスペースを消します
- `TRIM`：前後の空白を消します
- `ASC`：全角数字を半角にします
- `--`：文字列を数値に変換します
- `IFERROR(…,0)`：空のセルなど、数値にできないものを0として扱います

**根本的に直す方法（おすすめ）**
J列のデータそのものを数値に変えておくと、ほかの集計でも同じ問題が起きません。
- J2:J21を選択し、［データ］→［区切り位置］→ そのまま［完了］を押すと、数値に変換されます。
- 緑の三角が出ている場合は、［!］→［数値に変換する］でも変換できます。
- 今後CSVを取り込むときは、［データ］→［テキストまたはCSVから］（Power Query）を使い、J列の型を「整数」または「10進数」に指定しておくと安全です。

---

## 原因2：マイナスの金額があり、表示ではマイナスに見えていない

1,960 = 980 × 2 です。たとえば値引き行の実際の値が **-980** なのに、表示形式の都合で「980」や「(980)」、赤字の「980」に見えていたとします。電卓で +980 として足すと、ちょうど1,960の差になります。

**確かめ方**
```
=COUNTIF(J2:J21,"<0")
```
1以上ならマイナスの値があります。怪しいセルを選択し、数式バーに表示される実際の値を確認してください。

**直し方**
- この場合、Excelの合計（160,055）が正しく、電卓の計算が間違っています。
- 値引きを合計に含めない仕様なら、次の数式で正の金額だけを合計できます。
  ```
  =SUMIF(J2:J21,">0")
  ```

---

## 原因3：計算方法が「手動」になっている（または合計範囲が実データとずれている）

CSVを貼り付けたあとに再計算されず、古い合計が残っている可能性があります。また、行の挿入や削除によって、実際のデータ行がJ2:J21からずれていることもあります。

**確かめ方**
- ［数式］タブ →［計算方法の設定］が「自動」になっているか確認します。
- F9キーを押して、J22の値が変わるか確認します。
- J22をダブルクリックし、色枠で囲まれた範囲が電卓で足した20行と一致しているか確認します。

**直し方**
- 計算方法を「自動」に戻します。
- 範囲がずれていた場合は、実際のデータ範囲に合わせて数式を修正します。
- 行が増減しても範囲が崩れないように、表をテーブル化（Ctrl+T）しておく方法もあります。その場合、合計は次のように書けます。
  ```
  =SUM(テーブル1[金額])
  ```

---

### 最初に試すこと

まず原因1の「確かめ方」3の数式を入れてみてください。結果が **1960** なら、原因は文字列の混入でほぼ確定です。結果が0なら、原因2の `COUNTIF(J2:J21,"<0")` を確認してください。
