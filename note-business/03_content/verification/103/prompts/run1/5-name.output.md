# XLOOKUP の #NAME? の原因と直し方

## 結論

最も可能性が高い原因は、**Excel 2019 に XLOOKUP がないこと**です。XLOOKUP は Microsoft 365 と Excel 2021 以降で使える関数です。同僚の Microsoft 365 では動き、Excel 2019 では使えない関数として #NAME? になります。

---

## 考えられる原因（可能性の高い順）

### 1. Excel 2019 が XLOOKUP に対応していない（ほぼこれ）

**確かめ方**
- D2 を選び、数式バーを見ます。`=_xlfn.XLOOKUP(...)` のように頭に **`_xlfn.`** が付いていれば確定です。これは「この版では使えない新しい関数」という印です。
- 空いたセルで `=XLO` と入力します。候補一覧に XLOOKUP が出なければ未対応です。
- ［ファイル］→［アカウント］→［バージョン情報］で版を確認できます。

### 2. 関数名や記号が全角になっている（手で打ち直した場合）

`ＸＬＯＯＫＵＰ` や `（ ）`、`，` が全角だと、Excel が関数として認識できません。

**確かめ方**
数式バーで文字幅を見ます。全角は幅が広く見えます。日本語入力をオフにして打ち直し、直るかどうか試してください。

### 3. 「未登録」を囲む引用符が全角・スマートクオートになっている

`“未登録”` や `"未登録"` の引用符が半角 `"` でないと、文字列ではなく名前とみなされ #NAME? になることがあります。メールやチャットから数式をコピーしたときに起きがちです。

**確かめ方**
引用符を消して、日本語入力オフで半角 `"` を打ち直します。

※2・3は、1の `_xlfn.` が付いていない場合に疑ってください。

---

## 直した数式（Excel 2019 でも 365 でも動きます）

**案A：INDEX＋MATCH（おすすめ）**
```
=IFNA(INDEX(取引先マスタ!$B$2:$B$11,MATCH(C2,取引先マスタ!$A$2:$A$11,0)),"未登録")
```

**案B：VLOOKUP**
```
=IFNA(VLOOKUP(C2,取引先マスタ!$A$2:$B$11,2,FALSE),"未登録")
```

D2 に入力したら、下の行へコピーしてください。

**作るときの注意**
- MATCH の第3引数 `0`、VLOOKUP の第4引数 `FALSE` は**必ず入れてください**。省略すると近似一致になり、違う取引先名が出ることがあります。
- 見つからないときの処理は、XLOOKUP の第4引数の代わりに **IFNA** で行います。IFERROR でも動きますが、範囲の指定ミスなど他のエラーまで「未登録」と表示して隠してしまいます。
- 案Aは、マスタの列を入れ替えても参照がずれにくい点で案Bより安全です。

---

## 直したあとに「未登録」が出る場合

数式ではなくデータの問題です。次を確認してください。

- コードの前後に余分なスペースがある
  - 確かめ方：`=LEN(C2)` が 5 になるか
- `C-001` のハイフンや英字が全角になっている
- 請求明細とマスタで表記が違う
  - 確かめ方：`=C2=取引先マスタ!A2` で TRUE になるか

同僚とファイルをやり取りする場合は、両方の環境で動く案A・案Bに統一しておくと安心です。
