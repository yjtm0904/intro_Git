# 原因と直し方（#VALUE! ＝ 掛け算の相手に「数値にできない文字」がある）

## 原因1（最有力）：G7に「5個」という文字列が入っている

Excelは「5個」を数値として扱えません。そのため `=G7*H7` が #VALUE! になります。ほかの行は「1」「2」のような純粋な数値なので、7行目だけエラーになります。

**確かめ方**
- 空いているセルに `=ISNUMBER(G7)` と入れます。**FALSE** なら文字列です。
- 数式バーでG7を見て、「個」が実際に打ち込まれているかを確認します。
  - 表示形式で「個」を付けているだけなら、数式バーには「5」としか出ません。この場合は原因ではありません。

**直し方（おすすめ：データ側を直す）**
1. G7を `5` に打ち直します。
2. 「個」を表示したい場合は、G列を選んで「セルの書式設定」→「表示形式」→「ユーザー定義」に `0"個"` と入れます。

こうすると見た目は「5個」のまま、中身は数値になり、元の `=G7*H7` で **4320** が出ます。

**直し方（データを直せない場合：数式側で吸収する）**
```
=VALUE(SUBSTITUTE(G7,"個",""))*H7
```
J列全体に使う場合は、数値の行でも動くこの形が安全です。
```
=SUBSTITUTE(G7,"個","")*H7
```
（"1" のような数字の文字列は掛け算で自動的に数値になります。）

## 原因2：H7（またはG7）に見えない文字や単位が混じっている

次のような場合も #VALUE! になります。
- 「864円」のように単位が打ち込まれている
- Webやシステムからのコピーで、ノーブレークスペース（CHAR(160)）などが混入している

**確かめ方**
- `=ISNUMBER(H7)` を確認します。
- `=LEN(H7)` を確認します。「864」なら3になるはずで、4以上なら余計な文字があります。
- `=CODE(RIGHT(H7))` で末尾の文字コードを確認します。160ならノーブレークスペースです。

**直した数式**（スペース類と「個」「円」をまとめて除去）
```
=SUBSTITUTE(SUBSTITUTE(TRIM(SUBSTITUTE(G7,CHAR(160),"")),"個",""),"円","")
 *SUBSTITUTE(SUBSTITUTE(TRIM(SUBSTITUTE(H7,CHAR(160),"")),"個",""),"円","")
```
Microsoft 365なら、数字以外を消す方法がより簡潔です。
```
=--REGEXREPLACE(G7,"[^0-9.]","")*--REGEXREPLACE(H7,"[^0-9.]","")
```

## 原因3：G7・H7自体が数式で、その結果がエラーになっている

G7やH7が別の数式で計算されていて、その結果が #VALUE! だと、J7にもエラーがそのまま伝わります。

**確かめ方**
- G7・H7を選んで、数式バーに `=` で始まる数式がないかを確認します。
- `=ISERROR(G7)` と `=ISERROR(H7)` を確認します。TRUE なら参照元が原因です。

**直し方**
- 参照元の数式を先に直します。
- 応急処置として空欄表示にしたい場合は、次の数式を使います（エラーを隠すだけなので、原因の特定後に外すことをおすすめします）。
```
=IFERROR(G7*H7,"")
```

---

### まとめ
サンプルの状況からほぼ間違いなく**原因1**です。G7を「5」に直し、表示形式 `0"個"` で「個」を見せるのが最もきれいな解決です。元の `=G7*H7` のままで4320になります。
