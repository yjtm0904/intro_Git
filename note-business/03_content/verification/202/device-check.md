# 記事202 実機確認の手順書（オーナー用・約30分）

対象：`03_content/verification/202/Code.gs`（v1.0）／記事 `03_content/articles/202-gas-invoice-pdf-email-pack.md`
目的：Node.jsのテスト（`test-result.txt`、25件すべて成功）では確かめられない点を、Googleの実際の環境で確かめる。
確かめる点：権限の承認画面／PDFの見た目（A4・1ページ）／Gmailの下書き／送付記録／再実行で重複しないこと／一時ファイルが残らないこと。

安全のための約束
- 事業用（または検証用）のGoogleアカウントで行う。勤務先のアカウントや、実在の取引先のデータは使わない。
- データは `templates.md` の「テスト用の架空データ」だけを使う（会社名・アドレスはすべて架空）。
- テストモードは「ON」のまま行う。メールはすべて自分のアドレスあての下書きになり、送信はしない（手順10の任意の確認だけ、自分あてに1通送る）。

---

## 0. 準備（4分）

1. ドライブで新しいフォルダを作る（名前の例：請求書PDF_テスト）。フォルダを開き、URLの `folders/` より後ろの文字（フォルダID）をメモ帳にコピーしておく。
2. 新しいスプレッドシートを作る（名前の例：請求書パック_実機確認）。

## 1. コードを貼る（3分）

1. スプレッドシートのメニュー「拡張機能」→「Apps Script」を開く。
2. 最初からある `function myFunction() {}` を消し、`Code.gs` の全文を貼って保存する（Ctrl+S）。
3. 左の「プロジェクトの設定」（歯車）で、タイムゾーンが「(GMT+09:00) 日本標準時 - 東京」になっているかを見る。違えば直す。
   - [ ] タイムゾーンを確かめた（最初の表示：＿＿＿＿＿＿）

## 2. シートを作り、権限を承認する（4分）

1. スプレッドシートのタブに戻り、ページを再読み込みする。数秒後、メニューに「請求書」が出る。
   - [ ] 「請求書」メニューに「① 内容を確認する（作成しない）」「② PDFとメールを作成する」「準備：5枚のシートを作る」の3つがある
2. 「請求書」→「準備：5枚のシートを作る」を実行する。初回は承認の画面が出るので、自分のアカウントを選んで内容を確かめてから許可する。
   - 「このアプリは Google で確認されていません」のような画面が出た場合は、詳細を開いて自分のプロジェクト名であることを確かめてから進む（表示された文言をそのまま記録する）。
   - [ ] 承認画面に表示された権限を、表示どおりに書き写した：
     - ＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿
     - ＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿
     - ＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿
   - 記事では、Gmail（GmailApp。下書きに必要で、メールの閲覧・作成・送信・削除まで含む広い権限）、ドライブ（PDFの保存と一時ファイルの削除）、スプレッドシート（一時ファイルの作成）の3つと説明している。ほかの項目があれば書き足す。
3. もう一度「準備：5枚のシートを作る」を実行する（1回目は承認だけで終わることがある）。
   - [ ] 取引先マスタ・請求明細・送付記録・設定・請求書レイアウトの5枚ができた。「作成しました：…」と出た
   - [ ] もう一度実行すると「5枚ともあります。何も変えていません。」と出る

## 3. テスト用の架空データを入れる（3分）

1. `templates.md` の6章のとおり、取引先マスタのA2と請求明細のA2にデータを貼り、「データ」→「テキストを列に分割」で列に分ける。
   - [ ] 請求明細のA列（対象月）が「2026-11」のまま（日付に変わっていない）
   - [ ] 税率の列が「10%」「8%」と表示されている
2. 設定シートのB列に、`templates.md` の設定の値を入れる。PDF保存フォルダIDは手順0のID、テスト用の宛先は自分のアドレスにする。テストモードは「ON」、送信方法は「下書き」のまま。

## 4. 内容を確かめる（2分）

「請求書」→「① 内容を確認する（作成しない）」
- [ ] 「テストモード（宛先はすべて 自分のアドレス）／下書き」と出る
- [ ] 「作成する：3件（合計 67,394円）うちメール未登録（PDFだけ作る）1件」と出る
- [ ] C-001 53,949円／C-002 9,373円／C-003 4,072円（メール未登録）と並ぶ
- [ ] この時点で、ドライブのフォルダとGmailの下書きに何も増えていない

## 5. 作成する（3分）

「請求書」→「② PDFとメールを作成する」
- [ ] 「【テスト】下書きで3件を作成します。よろしいですか？」と出る → 「はい」
- [ ] 「終わりました」に「下書き済み：2件」「メール未登録：1件」と出る
- [ ] 「はい」を押してから終わるまでの時間：約＿＿秒（3件）

## 6. PDFの見た目（4分）

ドライブのフォルダを開く。
- [ ] 「【テスト】INV-202611-C-001_株式会社サンプル商事.pdf」など、3つのPDFがある
- C-001のPDFをダウンロードして、PDFを開くアプリで次を見る。用紙の大きさは、アプリのファイルのプロパティ（Macのプレビューなら「ツール」→「インスペクタ」）で確かめる。
  - [ ] 用紙：A4（Letterなど、ほかの大きさのときは記録する：＿＿＿＿）
  - [ ] 1ページに収まっている（2ページ目がない）
  - [ ] 文字化けがない。{{ }} のままの箇所がない
  - [ ] 宛名「株式会社サンプル商事 御中」、請求書番号「INV-202611-C-001」、発行日、支払期限「2026年12月31日」が入っている
  - [ ] ご請求金額「53,949円」。10%対象 46,500／消費税 4,650／8%対象 2,592／消費税 207／合計 53,949
  - [ ] 明細が取引日の順に3行。コーヒー豆の行の税率が「8%※」
  - [ ] 「登録番号 T0000000000000」と、軽減税率の注記が入っている
  - [ ] 枠線（グリッド線）が出ていない。罫線は明細と合計の欄だけ
  - 見た目で気になった点：＿＿＿＿＿＿＿＿＿＿＿＿

## 7. 下書きと送付記録（3分）

Gmailの「下書き」を開く。
- [ ] 下書きが2通（C-001とC-002）。宛先はどちらも自分のアドレス
- [ ] 件名「【テスト】【請求書】2026年11月分のご請求（株式会社見本サービス）」
- [ ] 本文の1行目が「※テスト用です。本番の宛先：sample-shoji@example.com」（C-002は sample-kogyo@example.com）
- [ ] PDFが1つ添付され、開くと手順6と同じ中身
- [ ] 送信済みフォルダに、このテストのメールがない

送付記録シートを開く。
- [ ] 3行ある。B列「テスト」、C列「2026-11」、I列は「下書き済み」2行と「メール未登録」1行（C-003）
- [ ] K列のURLを開くと、そのPDFが表示される

## 8. 再実行で重複しないこと（2分）

もう一度「② PDFとメールを作成する」を実行する。
- [ ] 「作るものはありません」「記録があるため作らない：3件」と出る
- [ ] ドライブのPDFは3つのまま、Gmailの下書きは2通のまま、送付記録は3行のまま

## 9. 一時ファイルが残っていないこと（1分）

- [ ] マイドライブに「作成中_請求書_2026-11」が残っていない（ゴミ箱に移っている）

## 10. 任意：送信の確認ダイアログ（時間があれば・3分）

1. 設定の送信方法を「送信」にする（テストモードは「ON」のまま）。送付記録のC-001の行のI列を「取消」に書き換える。
2. 「② PDFとメールを作成する」を実行する。
   - [ ] 「【テスト】送信で1件を作成します。よろしいですか？」と、「メールはすぐに送信され、取り消せません。」が出る → 「はい」
   - [ ] 自分のアドレスに1通届く（件名に【テスト】、PDFが添付）
3. 送信方法を「下書き」に戻す。

## 11. 後片付けと報告

- テストの下書き・PDF・スプレッドシートは削除してよい（ゴミ箱は30日後に自動で消える）。
- 次を事業責任者（Claude）に伝える。記事の冒頭の「動作確認日」「確認環境」と、権限の説明・エラー対処表を、確認の結果に合わせて直す。
  - 確認日：＿＿＿＿／アカウントの種類：個人（gmail.com）・Google Workspace のどちらか
  - 承認画面に出た権限の一覧（手順2）
  - PDFの用紙と、1ページに収まったか（手順6）。A4でなかった場合は、記事に書いた代わりの方法（書き出しURL）の採否を相談する
  - 3件にかかった時間（手順5）
  - チェックが付かなかった項目と、そのときの画面の表示（エラーの文言はそのまま）
