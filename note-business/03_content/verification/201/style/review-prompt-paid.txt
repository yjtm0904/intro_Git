あなたは文章の編集担当です。下の【原稿】を【ルール】で点検し、問題の箇所を一覧にしてください。

【ルール】
S1 1文目は場面から書く。「〜向けの記事です」「この記事では〜を紹介します」と記事が自分を説明しない
S2 見出しは結論の文にする。「結論：」「まとめ：」のラベルと、全記事共通の骨組みを使わない
S3 制作工程の言葉（「執筆とは別の新しい実行」「独立実行」）を使わない。検証のやり方は読者の言葉で1記事1回だけ書く（例：「記事を書いた会話とは別の新しい会話で2回試した」）
S4 同じ注意（出力の揺れ、他のAIは未検証、保証しない）は1記事1回。冒頭の検証情報か末尾の定型文に置く
S5 丸かっこの補足は1段落に1つまで。曜日・関数の引数を除き、1,000字あたり4つ以下を目安にする
S6 範囲の宣言（「この記事では〜しません」）は「扱わないこと」の1か所に集める
S7 「ないこと」の宣言を「あること」の事実に置き換える
S8 「〜ことがあります」「可能性があります」は、検証で起きた回数に置き換える（例：「16回中12回で」）
S9 1文は60字以内。80字を超えたら切る（URLは数えない）
S10 見出しの丸かっこ補足は記事全体で2つまで
S11 判断の足跡（試したこと→起きたこと→変えたこと）を前半に1つ置く。検証ログにある事実だけ
S12 検証情報と開示は「AIが何を作り、人が何をどう確かめたか」を具体的に書く
S13 定番のAI表現（「〜することが重要です」「いかがでしたか」「〜と言えるでしょう」などの決まり文句）を使わない
S14 同じ文末は3文まで。4文目は形を変える
S15 文例・プロンプト（コードブロック）は、実務の文書として自然かどうかで判断する。過剰な敬語と念押しだけを直す

【やり方】
- 原稿を書き直さない。問題の箇所と、どのルールに当たるかを一覧にする
- 修正案は「修正前→修正後」で、1か所につき1つまで
- 原稿にない体験・数字・事実を足さない。足りないときは【要確認：何が必要か】と書く
- コードブロックの中（文例・プロンプト）は、過剰な敬語と念押しだけを見る
- この原稿は有料記事の有料部分（購入した人だけが読む部分）。地の文（説明・見出し・注意書き）をルールで見る。コードブロックの中（プロンプト・完成例・コード）は、過剰な敬語と念押しだけを見る。場面の数・文例の内容・出力例は減らさない

【出力】
1. 一覧（行の引用／ルール番号／理由／修正案）
2. 人が判断すべき箇所（3つまで）

# コピペで使える事務のAI依頼文20場面｜メール・議事録・報告・お詫び【出力例つき】

## 使い方：共通の前置きと空欄の埋め方

20場面のどれを使うときも、最初に次の前置きを貼り、そのあとに場面の依頼文を貼ります。メモ帳などに保存しておくと、毎回コピーするだけで済みます。

```
あなたは、中小企業で事務を担当する私の文書作成を手伝います。次のルールを守ってください。
・【 】に書いた情報だけを使う。日付・数字・理由・約束・経緯を足さない
・足りない情報は推測で埋めず、その箇所に〔要確認：何が足りないか〕と書く
・〔 〕で囲んだ語は置き換え済みの記号なので、変えずに残す
・日付と曜日は入力のとおりに書く。「本日」「明日」などに言い換えない
・差出人と署名は、【差出人】があればそのとおりに、なければ〔自社〕〔氏名〕とだけ書く
・丁寧なビジネス文にする。二重敬語や、相手を責める・急がせる言い方は使わない
・出力は文面だけにする（【形式】で頼んだものは除く）。前置き・説明・複数の案は書かない
```

最初の版の前置きは、ルールが3つ（【 】の情報だけを使う、〔 〕の記号を残す、丁寧なビジネス文にする）でした。この版で場面1〜5を実行すると、次のことが起きました。

- 5場面すべてで、文面のあとに説明が付いた（「本文は宛名を含めて約246字です」「本日は11月8日なので、11月18日はまだ先の日付です」など）。コピーすると混ざる
- 5場面すべてで差出人の名前が入らず、署名の扱いも場面ごとに違った（何も書かない、「（署名）」とだけ書く）

そこで、文面だけを出すこと、差出人と署名の決まりを足しました。足りない情報を〔要確認〕と書くこと、日付を入力のとおりに書くこと、二重敬語や責める言い方を避けることも、あわせて足しています。直した版で20場面を実行し、Pythonと目視で点検しました。20場面の文面で、入力にない数字・曜日の誤り・記号の書き換えは0件です。

空欄（【 】の右側）の埋め方は次のとおりです。

- 会社名・人名・商品名は〔取引先A〕〔担当B〕〔商品Y〕のような記号にする
- 日付には曜日を付け、カレンダーで確かめてから書く
- 決まっていないことは書かない。足りないときは、AIが〔要確認：…〕と返す（検証では場面12・16で返った）
- 字数は上限の目安。検証では、字数の上限がある15場面すべてが上限内に収まった
- 出力の形（件名・項目・順番）は【形式】で決める。言い回しは毎回少しずつ変わる
- 見出しなどに「**」が付くことがある（チャットの画面では太字の印）。メールに貼って記号が残ったら消す

各場面は、依頼文（入力例を入れた状態）、出力例、NG例、送る前の確認点の順に載せています。出力例はClaudeで生成。AIの出力は毎回少しずつ変わります。NG例は、前置きなしの短い頼み方を実行した出力から、問題のある行を抜き出しています。

### 場面1 資料送付のお願い

依頼文（入力例を入れた状態）

```
【場面】取引先に資料の送付をお願いするメール
【相手】〔取引先A〕の〔担当B〕様（取引あり）
【欲しい資料】〔商品Y〕の仕様書（最新版）と価格表
【使い道】社内で来期の購入を検討するため
【期限】11月20日（金）
【送り方】メールにPDFで添付
【形式】件名をつける。本文は250字以内
```

出力例

```
件名：〔商品Y〕の仕様書（最新版）および価格表ご送付のお願い

〔取引先A〕
〔担当B〕様

いつもお世話になっております。〔自社〕の〔氏名〕です。

社内で来期の購入を検討するため、〔商品Y〕の仕様書（最新版）と価格表をお送りいただきたく、ご連絡いたしました。
お手数をおかけいたしますが、11月20日（金）までに、PDFにてメールに添付してお送りいただけますと幸いです。

どうぞよろしくお願いいたします。

〔自社〕
〔氏名〕
```

NG例：前置きなしで「取引先に資料を送ってもらうお願いのメールを書いて」とだけ頼んだ出力（抜粋）です。

```
【案件名】の件で、資料のご送付をお願いしたくご連絡いたしました。
（中略）
【〇月〇日（〇）】までにいただけますと幸いです。
（中略）
※ファイル容量が大きい場合は、共有リンク等でも問題ございません。
（中略）
TEL：【電話番号】
（中略）
具体的な状況（相手との関係性、資料の内容、期限の緊急度など）を教えていただければ、それに合わせて調整します。
```

問題点

- 空欄：案件名・資料名・期限が【 】のまま。署名には電話番号やメールアドレスの欄まで付いた
- 足された：頼んでいない条件「共有リンク等でも問題ございません」
- 文面の前後に、説明（補足3つ）と「調整します」という申し出が付いた

送る前の確認点

- 資料名と版（最新版）が入力どおりか
- 期限の日付と曜日をカレンダーで確かめる

NG例：前置きなしで「来週、取引先と打合せをしたいので日程調整のメールを書いて。候補は24日・26日・27日の午後」とだけ頼んだ出力（抜粋）です。

```
・11月24日（火）13:00〜17:00
（中略）
所要時間は1時間程度を予定しております。
形式は貴社へお伺いする形、またはオンラインのいずれでも対応可能です。

- 空欄：用件と相手の名前が〇〇のまま。署名には架空の電話番号（000-0000-0000）が入った
- 文面のあとに、AIが実行した日を基準にした確認（24日は「来週」ではなく再来週ではないか）が付いた

送る前の確認点

- 候補日の曜日をカレンダーで確かめる（3つとも）

### 場面5 誤送信・添付漏れのお詫び

依頼文（入力例を入れた状態）

```
【場面】資料の添付漏れのお詫びと再送
【相手】〔取引先A〕の〔担当B〕様
【何があったか】11月18日（水）15時ごろに送った「〔案件X〕資料送付のご案内」のメールに、資料を添付し忘れた
【対応】このメールに資料（PDF、1点）を添付する
【形式】件名をつける。本文は200字以内。おおげさにしない
```

出力例

```
件名：【再送】〔案件X〕資料送付のご案内

〔取引先A〕
〔担当B〕様

いつもお世話になっております。〔自社〕の〔氏名〕です。

11月18日（水）15時ごろにお送りした「〔案件X〕資料送付のご案内」のメールに、資料を添付しておりませんでした。申し訳ございません。

本メールに資料（PDF、1点）を添付いたしましたので、ご確認いただけますと幸いです。

どうぞよろしくお願いいたします。

〔自社〕
〔氏名〕
```

NG例：前置きなしで「添付を忘れたので謝るメールを書いて」とだけ頼んだ出力（抜粋）です。

```
先ほどお送りしたメールに、資料を添付しないまま送信してしまいました。
（中略）
お手数をおかけして申し訳ございません。
今後このようなことのないよう、送信前の確認を徹底いたします。
```

問題点

- 足された：約束「送信前の確認を徹底いたします」。添付漏れの連絡にしては重い

送る前の確認点

- 添付したファイルが正しいか、開いて確かめる
- 宛先を間違えた誤送信で、個人情報や社外秘が含まれていた場合は、このメールより先に社内の報告手順に従う

NG例：前置きなしで「営業の見積を断るメールを書いて」とだけ頼んだ出力（抜粋）です。

株式会社〇〇
（中略）
社内で慎重に検討いたしましたが、誠に恐縮ながら、今回はご提案を見送らせていただくこととなりました。
（中略）
- 理由を添える場合は「予算の都合により」「社内の方針変更により」「他社様のご提案と比較検討した結果」などを、「社内で慎重に検討いたしましたが、」の後に入れると自然です。

## 文章の手直しの2場面

### 場面19 きつい表現をやわらかくする

依頼文（入力例を入れた状態）

```
【場面】社内チャットのきつい文を、やわらかくする
【元の文】何度も言っていますが、領収書は原本を出してください。コピーでは精算できません。今月もまだ3人が出していません。
【残すこと】原本が必要なこと／コピーでは精算できないこと／まだ出していない人がいること
【形式】意味を変えずに言い回しだけ直す。原本が必要なことは、強調の言葉ではなく、理由（コピーでは精算できない）を添えて伝える。直した文のあとに、変えた点を2つまで書く
```

出力例

```
お疲れさまです。
領収書は、原本でのご提出をお願いいたします。コピーでは精算ができないため、原本が必要となります。
今月分は、まだ3名の方が未提出となっております。お心当たりの方は、原本のご提出をお願いいたします。

---
変えた点
1. 「何度も言っていますが」は相手を責める印象になるため削り、原本が必要な理由として「コピーでは精算ができないため」を添えました。
2. 「出してください」「出していません」を「ご提出をお願いいたします」「未提出となっております」に改め、依頼の形にしました。
```

検証では、【形式】を「お願いが任意に読めないようにする」とした版で、元の文にない強調の言葉が足されました。「強調の言葉は足さずに」と加えても同じでした（各1回）。そこで、必要なことを理由で伝えるように【形式】を書き換えています。

NG例：前置きなしで「この文をやわらかくして」と、元の文だけを貼った出力（抜粋）です。

```
**案1（標準的）**
> 繰り返しのご案内となり恐縮ですが、領収書は原本でのご提出をお願いいたします。コピーでは精算ができませんので、ご了承ください。なお、今月分はまだ3名の方がご提出前となっています。お手すきの際にご対応いただけますと助かります。
**案2（よりやわらかく、社内向け）**
> 何度かお伝えしているところですが、領収書は原本でご提出いただけますと幸いです。コピーですと精算の手続きができないため、ご協力をお願いします。今月分は、まだ3名の方のご提出が確認できていませんので、お心当たりの方はご確認いただけるとうれしいです。
```

問題点

- 意味が変わった：案1は「お手すきの際にご対応いただけますと助かります」、案2は「原本でご提出いただけますと幸いです」で、原本の提出が任意のお願いに読める
- 案が2つ出て、どちらを使うかを選ぶ必要がある

送る前の確認点

- 残すべき条件（原本・コピー不可・未提出）が全部残っているか
- お願いが「できれば」「お手すきの際に」になっていないか

### 場面20 長いメールの要約と返信案

依頼文（入力例を入れた状態）

```
【場面】取引先からの長いメールを要約し、返信の下書きを作る
【相手】〔取引先A〕の〔担当B〕様
【届いたメール】〔担当B〕様より：いつもお世話になっております。先日お願いした〔商品Y〕の件で、3点ご相談です。1点目、数量を100個から150個に増やしたいので、お見積りを出し直していただけますか。2点目、150個の場合でも、納期は12月18日（金）に間に合いますか。社内の予定があるため、できれば早めに知りたいです。3点目、12月分からは、請求書の宛先を〔部署G〕に変えてください。お手数ですが、よろしくお願いいたします。
【返信の方針】受け取ったことを伝える。見積と納期は、11月27日（金）までに回答する。請求書の宛先の変更は承知した
【形式】最初に要約を3行で。そのあとに返信の下書き（件名つき、本文250字以内）。納期に間に合うかどうかは書かない
```

出力例

```

---

**件名**：Re: 〔商品Y〕の件（ご相談3点を承りました）

〔取引先A〕
〔担当B〕様

いつもお世話になっております。〔自社〕の〔氏名〕です。
〔商品Y〕の件でご連絡をいただき、ありがとうございます。ご相談の3点、確かに承りました。

数量を150個に変更した場合のお見積りと、12月18日（金）の納期につきましては、11月27日（金）までにご回答いたします。

## 自社用に改造する依頼文（全文）

職場の決まりに合わせて、20場面の依頼文を直すための依頼文です。共通の前置きは付けずに、これだけを貼ります。

```
次の依頼文を、私の職場で使いやすい形に直してください。

【職場のこと】
・業種と人数：
・よく送る相手：
・文の決まり：（例：社内の連絡はチャット。件名の付け方）
・いつも入れる一文：
・入れてはいけない情報：（例：社員名は〔社員C〕のような記号にする）
【直し方】
・【 】の見出しは残す。職場で毎回書く情報があれば、見出しを足してよい
・共通の前置きのルール（情報を足さない、〔要確認〕と書く、〔 〕の記号を残す）に反する指示は入れない
・直した依頼文だけを出し、そのあとに変えた点を3つまで書く
【直す依頼文】
（20場面のどれかを貼る）
```

直った依頼文は、元の依頼文と同じく、共通の前置きのあとに貼って使います。直したら、一度は架空の入力で試し、出力の形を確かめてください。

## 送信前チェックリストと、AIに入れない情報の早見表

### 送信前チェックリスト（10項目）

- □ 宛先：To・CC・BCCが正しいか（社外への一斉送信はBCC）
- □ 宛名：会社名・部署・名前・敬称が正しいか
- □ 記号：〔 〕を元の名前に戻したか（「〔」で検索して0件か）
- □ 要確認：〔要確認：…〕が残っていないか
- □ 日付と曜日：カレンダーで確かめたか
- □ 数字：金額・件数・時刻が、元の資料と同じか（AIに計算させていないか）
- □ 約束：入力にない約束（電話する、再発防止など）が入っていないか
- □ 言い方：相手を責める・急がせる言い方になっていないか
- □ 添付：ファイルが付いているか、正しいファイルか
- □ 社外秘：社外に出せない情報が入っていないか

### AIに入れない情報の早見表

置き換えずに、入れないもの

- マイナンバー、給与・賞与、人事評価、健康や家族の情報
- 銀行口座・カードの番号、パスワード・ID・認証コード
- 未発表の数字や社内の決定、交渉中の条件、取引先から預かった資料

記号に置き換えて使うもの

- 会社名・取引先名 → 〔取引先A〕
- 人名 → 〔担当B〕〔社員C〕
- 電話番号・メールアドレス・社内のURL → 〔電話番号〕〔メールアドレス〕〔社内URL〕
- 金額 → 文面だけなら〔金額〕、表の相談なら「X,XXX円」の形

貼る直前に確かめること

- □ 勤務先が使ってよいと決めたAIか
- □ 〔 〕の記号以外に、名前・連絡先・番号が残っていないか
- □ 会社名・金額・口座・未発表の数字が残っていないか
- □ パスワード・ID・社内のURLが、貼る文や画像に入っていないか
- □ 置き換えの対応表（置換表）や元のファイルを、そのまま貼っていないか

置換表の作り方と、置き換えの漏れを検索で探す方法は、次の記事にあります。
