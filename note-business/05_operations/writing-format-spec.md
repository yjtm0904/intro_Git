# 原稿フォーマット仕様（全ライター共通）

noteのエディタにそのまま移せる形で原稿を書くためのルール。

## 1. ファイル

- 置き場所: `note-business/03_content/articles/NNN-英小文字スラッグ.md`（例: `001-chatgpt-meeting-minutes.md`）
- 先頭にメタ情報（YAML）を書く。GitHub上では表として表示されるので、本文と区別できる。

```yaml
---
id: "001"
title: "記事タイトル（28〜40字目安）"
type: free            # free / paid
price: 0              # 有料記事の価格（円）
target_reader: "誰の、どんな状況の悩みか"
primary_keyword: "主キーワード"
hashtags: ["#タグ1", "#タグ2", "#タグ3"]
magazine: "追加するマガジン名"
cta_to: ["導線先の記事ID"]
status: draft         # draft / reviewed / ready / published
---
```

## 2. 本文で使ってよい要素（noteで再現できるもの）

| 要素 | 書き方 | 用途 |
|---|---|---|
| 大見出し | `## 見出し` | 章 |
| 小見出し | `### 見出し` | 節（これより深い見出しは使わない） |
| 段落 | 2〜4文で改行 | スマホで読みやすくする |
| 太字 | `**強調**` | 1段落に1か所まで |
| 箇条書き・番号リスト | `- ` / `1. ` | 手順、チェックリスト |
| 引用 | `> ` | 公式情報の引用（出典を明記） |
| コードブロック | ```` ``` ```` | **プロンプトやテンプレ**（読者がコピーしやすい） |
| 区切り線 | `---` | 大きな話題の切り替え |
| リンク | `[文字](URL)` | 出典、関連記事 |

## 3. 使わない要素

- **表（テーブル）**: noteのエディタは表に非対応（外部の補助ツールが存在することから判断）。「・項目：内容」形式の箇条書きに置き換える。
- 4段階目以降の見出し、脚注、HTMLタグ、絵文字の多用。
- 画像: 本文に直接入れず、`［図解：何を示す図か／入れる要素］` と書く（マーケティング担当が制作）。

## 4. 有料ライン

有料記事では、有料にする位置に次の1行を入れる。noteで有料ラインをこの位置に設定したら、この行は削除する。

```
**━━━━━━ ここから有料（noteの有料ラインをこの位置に設定）━━━━━━**
```

## 5. 構成テンプレート

### 有料記事
1. タイトル（ベネフィットが具体的。誇大表現は使わない）
2. 導入: 誰の、どんな悩みを、どう解決するか（3〜5文）
3. この記事で手に入るもの（箇条書き3〜7個）
4. こんな人向け／向かない人（誠実さが購入率を上げる）
5. 無料パート: 価値の一部を実際に渡す（全体の15〜30%）
6. ━━ 有料ライン ━━
7. 本編（手順・テンプレ・具体例・つまずきポイント）
8. まとめと次の一歩（関連記事・マガジンへの導線）
9. 注意事項（情報の時点、ツール仕様の変更可能性、免責）

### 無料記事（集客・信頼構築用）
1. タイトル（主キーワードを前半に入れる）
2. 結論を先に（2〜3文）
3. 本文（見出しで流し読みできる構成）
4. まとめ
5. 関連する有料記事・マガジンへの自然な導線（押し売りはしない）

## 6. 分量の目安

- 無料記事: 3,000〜6,000字
- 有料記事: 価格が〜500円なら5,000字〜、〜1,500円なら10,000字〜、それ以上は15,000字〜。テンプレや実例の量を重視する（字数そのものは目的にしない）。

## 7. 文体

- です・ます調。1文は60字以内を目安にする。
- 「誰でも」「簡単に」「必ず」「放置で」は根拠なしに使わない。
- 筆者の実体験は**本当にある場合だけ**書く。ない場合は「検証してみた結果」「よくあるケース」として書く。
