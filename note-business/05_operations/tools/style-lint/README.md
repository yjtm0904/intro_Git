# style-lint（文体の機械チェック）

「AIっぽさ」を減らす編集の**工程1**（`02_strategy/style-guide.md` §4）で使う道具です。`patterns.json`（58パターン）を原稿の本文に当て、丸かっこの密度などを数え、§5 の機械の目安で点数を推定します。

## 使い方

```bash
cd /home/user/intro_Git/note-business
# 無料記事（本文すべて。末尾の定型文は除く）
python3 -I -B 05_operations/tools/style-lint/lint.py 03_content/articles/102-year-end-adjustment-reminders.md
# 有料記事の無料部分だけ（有料ラインの手前まで）
python3 -I -B 05_operations/tools/style-lint/lint.py --free-only 03_content/articles/203-year-end-admin-document-kit.md
# 道具の自己テスト（サンプル文で検出・非検出を確かめる）
python3 -I -B 05_operations/tools/style-lint/lint.py --self-test
```

- 終了コード：warn が1件でもあれば **1**、なければ0（使い方の誤りは2）。info は誤検出がありうる前提なので、目で確かめる。
- warn を残すときは、理由を審査記録（`04_review/` か `verification/<ID>/`）に書く（style-guide §4 工程1）。
- 複数の原稿を一度に渡せる。

## 点検の対象

- 除く：YAMLのメタ情報、コードブロック（文例・プロンプト）、HTMLコメント（`<!-- 変更理由 -->` など。複数行も可）、**末尾の定型文**（本文の最後の区切り線 `---` から後。常に除く）、`［図解：…］` `［画像：…］` の印（字数・かっこ・文の計測から除く）。
- `--free-only`：「ここから有料」の行の手前までを見る。付けないときは、有料ラインの行だけを除いて全体を見る。
- 出力の1行目に、対象の行の範囲と除いたものを出す。末尾に区切り線のない原稿では、途中の `---` から後が除かれるので、この範囲を確かめる。

## 出力の読み方

1. **行ごとの検出**：`L行番号 warn/info パターンid: 行の抜粋`。warn には直し方（patterns.json の suggest）を添える。最後に id ごとの件数。
2. **計測値**
   - 本文の字数：読者に見える文字（空白、`#`・`- `・`**` などの記号、URLを除く）。
   - 丸かっこ：`（` と `(` の数。**曜日のかっこ（`（金）`）、関数の引数（`FILTER(`）、リンクのURL、インラインコード**は数えない。日付を囲むかっこ `（11月24日（火））` の外側は1つと数える。1,000字あたりの値は小数1桁に丸めてから判定する（S5 の目安は4以下）。
   - 見出しの丸かっこ（S10：記事全体で2まで）。
   - 80字超の文（S9）：句点・！・？で文を切る。**かっこ（（）「」【】など）の中の句点では切らない**。行の終わりも文の区切りにする（句点のない行も1文と数える）。URLは数えず、句点・空白も数えない。この判定は patterns.json の `long-sentence` の正規表現の代わりに使い、同じ文を行ごとの検出（info）にも出す。
   - 「結論：」「まとめ：」のラベル見出しの数（S2）。参考として、ほかの「〇〇：」見出し（`### 文例1：…` など）の数も出す。
   - 同じ文末が4文以上続く箇所（S14）：文末の形（ます・ました・ません・です・でした・でしょう・ください・か、ほかは最後の1字）で比べる。文末の（…）【…】の補足は外して判定する。コードブロック・空行・コメントはまたいで数え、見出し・箇条書き・区切り線で数え直す。箇条書きの中の文は数えない（並列が自然なため）。
3. **点数の推定**（style-guide §5 の機械の目安だけ。3つの上限の小さいほう）
   - warn：0件→5、1〜2件→3、3件以上→2。定番の決まり文句（下の16種）が2件以上なら1。
   - 丸かっこ：4以下→5、6以下→4、9以下→3、9超→2。
   - 80字超の文：0→5、1以上→4。
   - 人の目安（1文目が場面か、見出しは結論の文か、同じ注意は1回か、判断の足跡が前半にあるか、検証ログにない体験・数字がないか）は、工程3〜5で人が確かめる。機械の点は上限の目安で、人の目安で下がることがある。
   - 定番の決まり文句として数える warn：open-many-people、open-this-article、open-conclusion-from、open-sonna-keiken、close-ikaga、close-saiwai、close-cheer、end-important、end-ieru、end-nodehanai、hedge-shisa、abstract-effect、hype、conj-kokode、self-answer、empathy。

## 限界

- patterns.json は1行ごとに照合する前提（調査レポート §6.5）。段落をまたぐ型は拾えない。照合の前に、リンクのURL部分とURLだけを消している。
- 丸かっこの数え方が調査レポート §5.1 の表と少し違う（102：調査9.1、この道具10.7）。前後の比較は、この道具の値どうしで行う。本文の字数は、URLのない203の無料部分で調査の値（3,617字）と一致した。
- 「最終更新日：…／動作確認日：…」のようなスラッシュ区切りの行も、80字を超えると「文」として数える（必須項目の行。直すかどうかは人が決める）。
- 文末の形は語尾の文字で比べているだけで、同じ「ます」でも単調に聞こえない場合がある。音読（工程4）で確かめる。
